制造执行系统（MES）数字化平台

符合 ISA-95 标准的微服务 MES 平台 — 覆盖排产、生产、质检、仓储全流程，支持多工厂协同

角色: 技术主管、核心架构 领域: 电子制造业 / MES 标准: ISA-95

项目背景

面向电子制造业搭建符合 ISA-95 标准的微服务 MES 平台，覆盖排产、生产、质检、仓储全流程，打通 ERP、HR、电子BOM 等系统，支持多工厂协同，消除数据孤岛、追溯难等行业问题。

🎯 核心目标
  • 覆盖 排产→生产→质检→仓储 全流程闭环
  • 打通 ERP/HR/电子BOM 系统，消除数据孤岛
  • 支持 多工厂协同，多租户数据隔离
  • 实现 USN 单件级双向追溯，原料到成品全链路可查

顶层多租户架构

拆分工单、工艺、生产、质量、设备、仓储六大业务域，实现多工厂数据隔离；封装通用技术底座，沉淀权限、异常处理等公共能力，统一团队开发规范。

  • 六大业务域拆分：工单域（排产/工单/派工）、工艺域（工艺路线/BOM/工艺参数）、生产域（工序执行/报工/流转）、质量域（质检/不良品/SPC分析）、设备域（设备台账/点检/OEE）、仓储域（物料/线边仓/退料），每个域独立部署独立演进
  • 多工厂数据隔离：基于租户ID实现多工厂数据物理/逻辑隔离，工厂A无法访问工厂B的生产数据与管理配置
  • 通用技术底座：封装权限管理（RBAC+数据权限）、异常处理（全局异常拦截+业务异常码标准化）、消息通知（站内信+WebSocket+短信）、日志审计（操作日志+数据变更日志）等公共能力
  • 统一开发规范：制定领域驱动设计（DDD）包结构规范、API接口规范、数据库设计规范，保障团队协作一致性
📐 六大业务域拓扑
工单域：排产计划 → 工单生成 → 派工调度
工艺域：工艺路线 → 电子BOM → 工艺参数
生产域：工序执行 → 报工登记 → 流转控制
质量域：来料检验 → 过程检 → 不良品管理 → SPC分析
设备域：设备台账 → 点检保养 → OEE效能分析
仓储域：物料入库 → 线边仓管理 → 退料处理

生产核心业务

工单全生命周期状态机

设计工单从创建到底层归档的全生命周期状态机，覆盖12种状态流转，严格管控状态变更规则，防止非法跳转。

  • 状态流转：待排产 → 已排产 → 已下发 → 生产中 → 已完工 → 已质检 → 已入库 → 已关闭
  • 异常分支：生产中可挂起/恢复，已质检可返工流转，不良品触发MRB评审流程
  • 状态变更管控：基于状态机模式强制校验，非法跳转（如待排产→已入库）直接拒绝，保障生产数据严谨性

四级版本化工艺模型

设计车间-产线-工艺-工序四级版本化工艺模型，支持工艺变更追溯与版本切换。

  • 车间级：定义车间整体生产能力与资源约束
  • 产线级：定义产线工艺路线与设备配置
  • 工艺级：定义完整工艺路线（BOM+工序序列+质量标准），版本化管理
  • 工序级：定义单工序的操作规范、工艺参数、检验标准
  • 版本化：工艺变更时留存历史版本，已下发工单继续使用旧版本，新工单自动匹配最新版本，版本切换可追溯
// 工单状态机 — 状态变更强制校验 @Component public class WorkOrderStateMachine { private static final Map<String, Set<String>> TRANSITIONS = Map.of( "PENDING", Set.of("SCHEDULED"), "SCHEDULED", Set.of("RELEASED"), "RELEASED", Set.of("IN_PRODUCTION", "SUSPENDED"), "IN_PRODUCTION", Set.of("COMPLETED", "SUSPENDED"), "SUSPENDED", Set.of("IN_PRODUCTION"), "COMPLETED", Set.of("INSPECTED", "REWORK"), "INSPECTED", Set.of("WAREHOUSED", "REWORK"), "REWORK", Set.of("IN_PRODUCTION"), "WAREHOUSED", Set.of("CLOSED") ); public void transition(WorkOrder order, String target) { String current = order.getStatus(); Set<String> allowed = TRANSITIONS.get(current); if (allowed == null || !allowed.contains(target)) { throw new IllegalStateTransitionException( "非法状态跳转: " + current + " → " + target); } order.setStatus(target); // 状态变更事件发布 eventBus.publish(new StatusChangedEvent(order)); } }

USN 单件级双向追溯体系

实现从原料到成品全链路数据可查、责任可定的 USN（Unique Serial Number）单件级双向追溯体系。

  • 正向追溯：原料批次 → 生产工单 → 工序记录 → 质检报告 → 成品SN，一键定位原料所生产的全部成品
  • 反向追溯：成品SN → 生产工单 → 工序记录 → 原料批次 → 供应商，一键定位成品所使用的全部原料
  • 数据采集：每个工序节点自动记录操作人、设备、时间、工艺参数、质检结果，形成完整生产履历

实时事件驱动

依托 RocketMQ 搭建生产事件总线解耦业务，结合 WebSocket + Redis 实现实时数据推送，满足生产看板与异常告警的实时性要求。

  • RocketMQ 生产事件总线：工序完成事件、质检事件、设备异常事件、物料消耗事件通过 RocketMQ 解耦发布，各业务域独立订阅处理，避免业务耦合导致的联级故障
  • WebSocket + Redis 实时推送：生产看板通过 WebSocket 订阅实时数据频道，Redis 缓存最新生产数据（当日产量、不良率、OEE），避免频繁查询数据库
  • 异常实时告警：设备故障、品质异常、物料短缺等事件触发实时告警，通过 WebSocket 推送至生产看板与相关人员终端
// 生产事件总线 — 工序完成事件驱动 @Component public class ProductionEventBus { @Autowired private RocketMQTemplate rocketMQTemplate; // 工序完成后发布事件 public void onOperationCompleted(OperationRecord record) { // 发布工序完成事件 rocketMQTemplate.send("PRODUCTION_OPERATION_COMPLETED", new OperationCompletedEvent(record)); // 通知生产看板实时刷新 rocketMQTemplate.send("DASHBOARD_REFRESH", new DashboardRefreshEvent( record.getWorkOrderId(), record.getCompletedQuantity())); } // 独立订阅 — 质检域自动触发来料检验 @RocketMQMessageListener(topic = "PRODUCTION_OPERATION_COMPLETED") public void onMessage(OperationCompletedEvent event) { if (event.getOperationType() == OperationType.INSPECTION) { qualityService.autoTriggerInspection( event.getWorkOrderId()); } } }
