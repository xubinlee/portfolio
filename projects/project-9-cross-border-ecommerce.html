自研跨境电商国家站平台

越南·泰国·印尼·俄罗斯 — 从"依赖第三方平台"到"自有品牌独立站出海"的战略转型

角色: 项目Leader、高级开发 站点: 越南 / 泰国 / 印尼 / 俄罗斯 状态: 生产运行中

项目概述

主导自研跨境电商国家站平台，覆盖越南、泰国、印尼、俄罗斯4个国家站点，实现从"依赖第三方平台"到"自有品牌独立站出海"的战略转型。基于 Spring Cloud Alibaba 微服务架构，构建技术中台+业务中台双层体系，支撑多国本地化运营与跨境供应链协同。

🎯 核心成就
  • 覆盖 4个国家站点，支撑海外本地化运营
  • 技术中台+业务中台双层体系，核心能力复用率 > 80%
  • 接入 6+ 本地支付渠道（Momo/ZaloPay/PromptPay/OVO/Dana/Yandex Pay）
  • 实现从"依赖第三方平台"到"自有品牌独立站"的战略转型

微服务架构设计

基于 Spring Cloud Alibaba 构建技术中台+业务中台双层体系，底层核心微服务支撑上层业务快速迭代，公共组件沉淀降低重复建设成本。

  • 底层核心微服务：注册中心（Nacos）、API网关（Spring Cloud Gateway WebFlux）、认证中心（OAuth2）、用户权限管理、工作流引擎（Flowable 8.0），统一技术底座支撑多国业务
  • 业务中台服务：商品中心、订单中心、支付中心、物流中心、营销中心，各国家站点按需组装，共享核心业务逻辑
  • 公共组件沉淀：安全组件（加解密/防篡改）、数据组件（多数据源/读写分离）、审计组件（操作日志/数据变更追踪）、多租户组件（TenantLineHandler/TenantBroker）、缓存组件（Redis多级缓存）、Feign组件（统一拦截器/熔断降级）
📐 双层架构拓扑
技术中台：Nacos注册中心 + Gateway网关 + OAuth2认证 + 用户权限 + Flowable工作流 + 公共组件库
业务中台：商品中心 + 订单中心 + 支付中心 + 物流中心 + 营销中心
国家站点：越南站 / 泰国站 / 印尼站 / 俄罗斯站 — 复用中台能力，差异化本地配置

多租户 SaaS 架构

设计共享数据库+租户字段逻辑隔离方案，确保多国家站点数据安全隔离的同时最大化资源利用率。

  • 共享数据库 + 租户字段逻辑隔离：每个国家站点作为独立租户，共享同一数据库实例，通过 tenant_id 字段实现逻辑隔离，降低基础设施成本
  • MyBatis-Plus TenantLineHandler 插件：SQL 自动注入租户过滤条件，业务代码零侵入，SELECT/INSERT/UPDATE/DELETE 全自动拼接 tenant_id 条件
  • TenantBroker 租户切换器：支持异步线程/定时任务中安全切换和还原多租户系统中的租户ID，解决跨站点数据查询与批量任务场景下的租户上下文混乱问题
  • DataScope 数据权限拦截器：实现行级数据隔离，支持全部/本部门/本部门及下级/仅本人等多级数据范围控制，确保即使在同一租户内也能按组织架构隔离数据

统一安全体系

基于 Spring Authorization Server 构建统一安全体系，一套认证机制覆盖多国家站点、多端接入场景。

  • OAuth2 授权服务器：基于 Spring Authorization Server 实现，支持密码模式、短信模式、客户端模式三种认证方式，覆盖用户端、管理后台、第三方系统多端场景
  • 自定义 Token 内省器：支持 Bearer Token + API Key 双模式鉴权，Bearer Token 用于浏览器/移动端，API Key 用于第三方系统对接与自动化脚本
  • @HasPermission 注解：实现按钮级权限控制，支持权限表达式（如 @HasPermission("order:export")），前端菜单+后端接口双重校验，杜绝越权访问
  • @Inner 注解 + AOP 切面：内部服务调用安全隔离，仅允许携带内部标识的 Feign 调用访问标注 @Inner 的接口，外部请求直接拒绝
// 双模式Token内省 — Bearer Token + API Key @Component public class CustomTokenIntrospector implements OpaqueTokenIntrospector { @Override public OAuth2AuthenticatedPrincipal introspect(String token) { // 模式1: Bearer Token — 标准OAuth2流程 if (token.startsWith(SecurityConstants.BEARER)) { return introspectBearerToken(token); } // 模式2: API Key — 第三方系统对接 if (token.startsWith(SecurityConstants.API_KEY_PREFIX)) { return introspectApiKey(token); } throw new BadOpaqueTokenException("无效的Token格式"); } }

跨境支付网关

策略模式 + 工厂模式统一接入各国本地支付渠道，多币种实时汇率转换 + 跨境结算对账。

  • 策略模式 + 工厂模式统一接入：抽象支付渠道接口（创建订单/查询/退款/回调），各本地支付渠道实现独立策略类，工厂类根据国家+渠道类型自动路由
  • 本地支付渠道覆盖：越南 Momo/ZaloPay、泰国 PromptPay、印尼 OVO/Dana、俄罗斯 Yandex Pay，支持钱包支付、扫码支付、网银转账等多种支付方式
  • 多币种实时汇率转换：接入外汇API实时汇率 + Redis缓存，下单时锁定汇率存Redis，避免汇率波动导致对账不平
  • 跨境结算对账：XXL-Job定时拉取各渠道结算账单，与系统订单明细逐笔匹配，差异自动标记并推送预警
// 支付渠道策略工厂 @Component public class PaymentChannelFactory { private final Map<String, PaymentChannel> channelMap; public PaymentChannelFactory(List<PaymentChannel> channels) { this.channelMap = channels.stream() .collect(Collectors.toMap( c -> c.getClass() .getAnnotation(PaymentType.class).value(), Function.identity())); } public PaymentChannel getChannel(String countryCode, String paymentMethod) { String key = countryCode + "_" + paymentMethod; PaymentChannel channel = channelMap.get(key); Assert.notNull(channel, "不支持的支付渠道: " + key); return channel; } } // 示例：越南Momo支付 @PaymentType("VN_MOMO") @Component public class MomoPaymentChannel implements PaymentChannel { @Override public PaymentResult createOrder(PaymentRequest req) { // Momo API签名 + 请求 String signature = hmacSHA256(req, momoSecretKey); return momoClient.createOrder(req, signature); } @Override public PaymentResult query(String orderId) { return momoClient.queryOrder(orderId); } }

自动化运维

Jenkins Pipeline CI/CD 全链路自动化 + 质量门禁 + 可观测性监控，保障多站点稳定运行。

  • Jenkins Pipeline CI/CD：Git Push → Maven 编译 → JaCoCo 覆盖率检测 → SonarQube 质量门禁（阻断 Bug/漏洞）→ Docker 镜像构建 → 容器化部署，全链路自动化
  • JaCoCo + SonarQube 质量门禁：代码覆盖率不达标、Bug/漏洞发现时自动阻断发布流程，确保多站点代码质量一致性
  • Docker Compose 容器化部署：标准化的容器编排，支持多环境（dev/test/uat/prod）一键部署，降低环境差异导致的问题
  • 可观测性监控：SkyWalking 全链路追踪 + ELK 日志检索 + Prometheus 指标监控，多站点统一监控大屏
