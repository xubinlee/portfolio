全域电商业务平台

CRM / OMS / WMS / TMS / FMS / BI — 打通多渠道、多系统、跨国内外电商的数据链路，实现业财一体化

角色: 技术负责人 领域: 全域电商中台 状态: 生产运行中

项目背景

各业务系统（第三方ERP、金蝶财务、自研系统、第三方物流）形成数据孤岛，订单-仓储-财务数据割裂，人工对账耗时易错。主导构建全域电商业务中台，打通多渠道、多系统、跨国内外电商的数据链路。

🎯 核心目标
  • 打通 CRM / OMS / WMS / TMS / FMS / BI 六大业务域数据链路
  • 对接 领星/马帮/管易云 等第三方ERP系统
  • 实现 平台账单→支付流水→财务凭证 三层对账自动化
  • 对账效率提升 20x+，人工对账耗时从数天降至分钟级

基础设施与网关

  • Nacos 服务发现 + 多环境配置隔离：支持 dev/test/uat/prod 多环境配置隔离，配置热加载无需重启服务
  • Spring Cloud Gateway 统一网关：统一入口路由 + Redis 令牌桶实现租户级/IP级双重限流，保障多系统接入场景下的流量管控

OMS — 订单管理系统

多渠道订单统一接入与智能调度，实现订单全生命周期管理。

  • 适配器模式 + 配置化路由规则：多渠道订单（Shopee/Lazada/TikTok Shop/自营站）通过适配器模式统一归一化处理，路由规则通过 Nacos 配置热加载，无需重启即可调整路由策略
  • 智能调度引擎：按仓库距离/库存水位/物流成本多维度加权评分，自动选择最优履约仓库，最大化降低履约成本
  • Flowable 工作流编排：使用 Flowable 编排拆单/合单/换仓流程，支持人工审批节点与异常处理分支
  • 最终一致性保障：本地事务 + RocketMQ 事务消息保证订单状态与库存扣减的最终一致性，订单创建→库存预占→支付确认→库存实扣全链路可靠
// 订单履约路由 — 多维度加权评分 @Component public class OrderFulfillmentRouter { public Warehouse selectOptimal(List<Warehouse> warehouses, Order order) { return warehouses.stream() .max(Comparator.comparingDouble(w -> scoreByDistance(w, order.getAddress()) * 0.4 + scoreByInventory(w, order.getSkus()) * 0.35 + scoreByLogisticsCost(w, order) * 0.25 )) .orElseThrow(() -> new NoAvailableWarehouseException()); } }

WMS — 仓储管理系统

以四层库存模型为基础，构建三层库存防超卖体系，确保库存数据的绝对准确。

  • 四层库存模型：可售库存（available）/ 在途库存（in_transit）/ 锁定库存（locked）/ 残次库存（defective），精细化区分库存状态，支持多维度库存查询
  • 三层库存防超卖体系：
    L1 · Redis Lua 原子预占：扣减前先原子预占库存，脚本保证检查+扣减的原子性，避免高并发超卖
    L2 · RocketMQ 延时消息超时释放：未支付订单的预占库存通过延时消息自动释放（默认15分钟），防止库存永久锁定
    L3 · XXL-Job 定时对账兜底：每小时对比 Redis 预占与 DB 实际库存，发现差异自动修正并告警
// Redis Lua 库存原子预占 private static final String LUA_PRE_OCCUPY = "local stock = redis.call('HGET', KEYS[1], ARGV[1]) " + "if stock and tonumber(stock) >= tonumber(ARGV[2]) then " + " redis.call('HINCRBY', KEYS[1], ARGV[1], -ARGV[2]) " + " redis.call('HSET', KEYS[2], ARGV[3], ARGV[2]) " + " return 1 " + "else " + " return 0 " + "end"; public boolean preOccupy(String sku, int quantity, String orderId) { Long result = redisTemplate.execute( new DefaultRedisScript<>(LUA_PRE_OCCUPY, Long.class), Arrays.asList( "stock:available:" + warehouseId, "stock:locked:" + warehouseId), sku, String.valueOf(quantity), orderId); return result != null && result == 1; }

TMS — 运输管理系统

策略模式 + 工厂模式封装物流商选择算法，RocketMQ驱动的轨迹推送与WebSocket实时刷新。

  • 策略模式 + 工厂模式封装物流商选择算法：按时效优先/成本优先/清关能力三个维度加权评分，工厂类根据订单目的国+包裹属性自动路由最优物流商
  • RocketMQ 驱动轨迹推送：物流商回传轨迹事件经 RocketMQ 异步处理，解耦轨迹接收与业务处理，支持轨迹异常实时告警
  • WebSocket 实时刷新：前端通过 WebSocket 订阅订单轨迹更新，无需轮询即可实时查看物流状态
  • 适配器模式统一账单格式：各家物流商账单格式差异通过适配器模式统一转换，屏蔽底层差异，自动生成标准化对账单
// 物流商选择算法 @Component public class LogisticsSelector { public LogisticsProvider select(Order order) { List<LogisticsProvider> candidates = providerRepo.findByCountry(order.getDestCountry()); return candidates.stream() .max(Comparator.comparingDouble(p -> scoreByTransitTime(p, order) * 0.35 + scoreByCost(p, order) * 0.35 + scoreByCustomsCapability(p) * 0.30 )) .orElseThrow(() -> new NoLogisticsAvailableException()); } }

第三方 ERP 集成

适配器模式对接领星/马帮/管易云等第三方ERP，支持 OpenAPI/Webhook/MQ 三种同步通道，限流熔断 + 断点续传保障集成稳定性。

  • 适配器模式统一对接：领星/马帮/管易云等第三方ERP接口差异通过适配器模式透明化，业务层无需感知底层接口差异
  • 三种同步通道：OpenAPI 主动拉取（定时同步）、Webhook 被动接收（实时推送）、MQ 异步消息（削峰填谷），根据业务场景灵活选择
  • 限流熔断 + 断点续传：Sentinel 限流保护第三方API不被过度调用，Redis 记录同步进度支持断点续传，服务重启后自动从上次中断位置继续

业财一体 — 三层对账

构建平台账单对账→支付账单对账→财务凭证生成三层对账体系，实现全链路业财一体化。

📊 三层对账体系
L1 · 平台账单对账：XXL-Job 分片并行拉取电商平台结算账单，与系统订单明细逐笔匹配，差异自动标记
L2 · 支付账单对账：支付流水与订单金额自动核销，多币种汇率锁定杜绝汇率波动造成对账不平
L3 · 财务凭证生成：配置化科目映射，RocketMQ 异步推送金蝶，定时对账兜底保障

L1 · 平台账单对账

  • XXL-Job 分片并行拉取：按店铺维度分片，多个 Executor 并行拉取各电商平台结算账单，Redis 记录拉取进度支持断点续传
  • 逐笔匹配 + 差异标记：账单明细与系统订单逐笔匹配（平台订单号+金额+时间），匹配成功自动确认，差异自动标记为待处理并推送预警

L2 · 支付账单对账

  • 策略模式 + 工厂模式统一接入多渠道支付：各支付渠道对账单格式差异通过策略模式透明化，统一返回标准化对账数据结构
  • Seata AT 保证核销-状态更新事务一致性：支付流水核销与订单状态更新绑定在同一分布式事务中，保证核销记录与订单状态的一致性
  • 多币种汇率锁定：下单时记录汇率→支付时锁定汇率存Redis→对账时使用锁定汇率换算，杜绝汇率波动导致对账不平
// 多币种汇率锁定 @Component public class ExchangeRateLock { // 下单时记录汇率 public void recordRateOnOrder(String orderId, String fromCurrency, String toCurrency) { BigDecimal rate = exchangeRateService.getRate( fromCurrency, toCurrency); // 锁定汇率，有效期30天 redisTemplate.opsForValue().set( "rate:lock:" + orderId, rate.toPlainString(), Duration.ofDays(30)); } // 对账时使用锁定汇率 public BigDecimal getLockedRate(String orderId) { String rate = redisTemplate.opsForValue() .get("rate:lock:" + orderId); Assert.notNull(rate, "订单汇率已过期或不存在: " + orderId); return new BigDecimal(rate); } }

L3 · 财务凭证生成

  • 配置化科目映射：业务单据类型与财务科目通过配置化映射表管理，新增业务类型只需配置不需改代码，支持 Nacos 热加载
  • RocketMQ 异步推送金蝶：对账完成的对账记录通过 RocketMQ 异步生成财务凭证并推送金蝶，削峰填谷保障系统稳定性
  • XXL-Job 定时对账兜底：每小时检查推送状态，匹配失败/推送失败自动重试，达到阈值推送预警
