AI分布式多智能体智能库存管理系统

大模型 + 多智能体 + EDA双引擎 — 全流程智能化盘点系统，盘点任务自动化、差异分析智能化、报告生成标准化

角色: 技术主管、AI架构 分类: AI / Multi-Agent 状态: 生产运行中

项目背景

传统仓储盘点依赖人工操作，存在效率低、误差大、流程不规范等痛点。引入大模型与多智能体技术打造全流程智能化盘点系统，实现盘点任务自动化、差异分析智能化与报告生成标准化。

🎯 核心价值主张
  • 盘点效率提升 10x+，人工干预率降低至 < 5%
  • 差异分析准确率 > 95%，异常归因可追溯
  • 报告生成从小时级降至 分钟级，格式标准化
  • 支持 Human-in-the-Loop 人工介入纠错与复盘迭代

分层多智能体架构

对标业界先进的 A2A 智能体通信标准，设计三级协作拓扑，采用 ReAct 决策模式实现复杂任务自主拆解、分布式协同与动态调度。

  • 监督智能体 (Supervisor Agent)：顶层编排中枢，负责盘点任务的全局规划、子任务拆解与分发、执行状态监控与异常兜底，基于 ReAct 模式自主决策下一步行动
  • 领域智能体 (Domain Agent)：按业务领域划分的专业智能体——库存查询Agent、盘点执行Agent、差异计算Agent、异常分析Agent、报告生成Agent，各司其职、独立演进
  • 工具智能体 (Tool Agent)：标准化封装底层业务能力接口——数据库查询、ERP对接、文件导出、消息通知等，通过 MCP 协议暴露为可调用工具，支持热插拔
📊 三级协作拓扑
L1 · 监督智能体：全局编排 + 任务拆解 + 状态监控 + 异常兜底
L2 · 领域智能体：库存查询 / 盘点执行 / 差异计算 / 异常分析 / 报告生成
L3 · 工具智能体：DB查询 / ERP对接 / 文件导出 / 消息通知 / MCP工具

通信标准：A2A Protocol，支持能力发现(Capability Discovery)与服务编排(Service Orchestration)

StateGraph 工作流编排

基于 Spring AI Alibaba Graph 实现类 LangGraph 的有状态工作流引擎，设计七节点流程链路，支持条件分支路由、人工干预中断恢复及状态持久化。

  • 七节点流程链路：EDA优化 → 库存查询 → 盘点执行 → 差异计算 → 异常分析 → 复盘决策 → 人工审核，每个节点独立状态管理与错误恢复
  • 条件分支路由：根据差异率阈值、异常等级、业务规则动态路由——低差异自动通过、中差异触发复盘、高差异人工审核
  • Human-in-the-Loop：在复盘决策与人工审核节点支持中断挂起，等待人工确认/修正后恢复执行，兼顾AI自动化与业务灵活性
  • 状态持久化：工作流状态快照持久化到 Redis，支持任务中断恢复、断点续跑、历史回溯
// StateGraph 七节点工作流定义 @Bean public StateGraph<InventoryState> inventoryWorkflow() { return new StateGraph.Builder<>(InventoryState.class) .addNode("eda_optimize", this::edaOptimize) .addNode("query_stock", this::queryStock) .addNode("execute_count", this::executeCount) .addNode("calc_diff", this::calcDifference) .addNode("analyze_anomaly",this::analyzeAnomaly) .addNode("review_decision",this::reviewDecision) .addNode("human_audit", this::humanAudit) .addEdge(START, "eda_optimize") .addEdge("eda_optimize", "query_stock") .addEdge("query_stock", "execute_count") .addEdge("execute_count","calc_diff") .addConditionalEdge("calc_diff", this::routeByDiffRate, Map.of("auto_pass", END, "review", "analyze_anomaly", "human_audit","human_audit")) .addEdge("analyze_anomaly", "review_decision") .addConditionalEdge("review_decision", this::routeByDecision, Map.of("approved", END, "recount", "execute_count", "escalate", "human_audit")) .addEdge("human_audit", END) .build(); }

AI工具网关建设

基于 MCP 协议标准化封装业务能力接口，依托 Nacos 实现工具服务动态注册与发现，解耦大模型智能体与业务系统，支持 Skill 插件热插拔。

  • MCP 协议标准化：统一工具定义规范（名称/描述/参数Schema/返回格式），大模型通过标准化接口调用业务能力，无需感知底层实现差异
  • Nacos 动态注册发现：工具服务启动时自动注册到 Nacos，智能体通过服务发现获取可用工具列表，支持运行时动态扩缩容
  • Skill 插件热插拔：新增盘点策略/对接新ERP/接入新数据源只需开发 Skill 插件并注册，无需修改智能体核心逻辑
  • 解耦大模型与业务系统：工具网关作为中间层，隔离大模型推理与业务系统调用，任何一方变更不影响另一方
// MCP 工具注册示例 @McpTool(name = "query_inventory", description = "查询指定仓库的库存数据") public class InventoryQueryTool { @ToolAction(description = "按仓库和SKU查询实时库存") public InventoryResult query( @Param(name = "warehouseId", description = "仓库ID") String warehouseId, @Param(name = "skuCodes", description = "SKU编码列表") List<String> skuCodes) { return inventoryService.queryRealtime(warehouseId, skuCodes); } @ToolAction(description = "查询历史盘点差异趋势") public DiffTrendResult diffTrend( @Param(name = "warehouseId", description = "仓库ID") String warehouseId, @Param(name = "period", description = "统计周期") String period) { return diffAnalysisService.getTrend(warehouseId, period); } }

分层记忆工程体系

构建「短期上下文记忆 + 长期业务记忆」分层记忆架构，结合 AutoContextMemory 上下文压缩与 Mem0 云端记忆服务，实现业务认知持续迭代，同时降低大模型 Token 消耗，有效控制推理成本。

  • 短期上下文记忆 (Working Memory)：当前盘点会话的上下文管理，采用 AutoContextMemory 滑动窗口 + 摘要压缩，在 Token 预算内保留高信息密度内容，避免关键信息被截断
  • 长期业务记忆 (Long-term Memory)：基于 Mem0 云端记忆服务持久化存储历史盘点经验、差异模式库、异常归因知识，跨会话复用业务认知
  • AutoContextMemory 上下文压缩：智能评估上下文各要素的信息价值，优先裁剪冗余内容保留决策依据，将 Token 消耗降低 40%+
  • 记忆迭代闭环：每次盘点结果自动沉淀为长期记忆，持续优化差异识别与异常归因的准确率，实现"越用越准"的业务认知进化
🧠 记忆分层架构
L1 · 短期上下文：当前会话滑动窗口 + AutoContextMemory 压缩 → 毫秒级访问
L2 · Mem0 云端记忆：历史盘点经验 + 差异模式库 + 异常归因知识 → 秒级检索
L3 · 业务知识图谱：领域规则 + 仓库特性 + SKU关联 → 持久归档

Token 消耗优化：AutoContextMemory 压缩率 > 40%，推理成本降低 > 30%

双引擎决策机制

首创「大模型语义分析 + EDA 分布估计算法全局优化」双引擎架构，利用大模型完成差异语义识别与异常归因，通过 EDA 算法对盘点数据进行全局进化校准，解决大模型数值幻觉与局部最优问题。

  • 大模型语义分析引擎：利用 LLM 的语义理解能力，完成差异原因自然语言解释、异常模式识别、非结构化数据（如备注/照片）理解，擅长"定性分析"
  • EDA 分布估计算法引擎：基于概率模型的进化优化算法，对盘点数据进行全局分布估计与进化校准，通过选择-变异-采样迭代逼近最优解，擅长"定量优化"
  • 双引擎协同：大模型识别差异语义 → EDA 进行全局数值校准 → 大模型解释校准结果 → 迭代收敛，互补解决大模型数值幻觉与 EDA 语义缺失问题
  • 幻觉抑制：EDA 引擎作为"事实校准器"，对大模型输出的数值结果进行交叉验证，偏差超阈值自动触发重新推理
// 双引擎协同决策核心逻辑 public class DualEngineDecision { private final LLMEngine llmEngine; private final EDAEngine edaEngine; public DecisionResult decide(InventoryContext ctx) { // Step 1: 大模型语义分析 — 识别差异原因 SemanticResult semantic = llmEngine.analyzeDiff(ctx); // Step 2: EDA全局校准 — 进化优化数值结果 EDAResult calibrated = edaEngine.optimize( ctx.getCountData(), semantic.getDiffPattern()); // Step 3: 交叉验证 — 抑制大模型数值幻觉 if (calibrated.deviation() > HALLUCINATION_THRESHOLD) { semantic = llmEngine.reAnalyze(ctx, calibrated.feedback()); calibrated = edaEngine.reOptimize(semantic); } // Step 4: 大模型生成自然语言解释 String explanation = llmEngine.explain( semantic, calibrated); return new DecisionResult( calibrated.optimalValues(), explanation, calibrated.confidence()); } }

AI安全治理体系

构建 Prompt 注入防护、SQL 语法白名单校验、数据权限沙箱三层防护，严格拦截增删改等危险操作，确保 AI 调用业务系统的安全性。

  • Prompt 注入防护：多层防线——输入层 Pattern Matching 检测已知攻击模式 + LLM 判断层识别语义级注入 + 输出层安全过滤拦截敏感内容泄露
  • SQL 语法白名单校验：AI 生成的数据库查询语句必须通过白名单校验，仅允许 SELECT 操作，严格拦截 INSERT/UPDATE/DELETE 等危险操作
  • 数据权限沙箱：AI 调用业务接口时自动注入租户隔离与数据范围约束，确保智能体只能访问授权范围内的数据，杜绝越权访问
  • 操作审计日志：全链路记录 AI 调用链路（Prompt → Tool → Result），支持事后追溯与合规审计
// SQL白名单校验拦截器 @Component public class SqlWhitelistInterceptor { private static final Set<String> ALLOWED_PREFIXES = Set.of("SELECT", "SHOW", "DESCRIBE", "EXPLAIN"); private static final Set<String> BLOCKED_KEYWORDS = Set.of("INSERT", "UPDATE", "DELETE", "DROP", "ALTER", "CREATE", "TRUNCATE", "GRANT"); public void validate(String sql) { String normalized = sql.trim().toUpperCase(); // 拦截危险操作 for (String keyword : BLOCKED_KEYWORDS) { if (normalized.contains(keyword)) { throw new SecurityException( "AI安全拦截: 禁止执行 " + keyword + " 操作"); } } // 校验白名单前缀 boolean allowed = ALLOWED_PREFIXES.stream() .anyMatch(normalized::startsWith); if (!allowed) { throw new SecurityException( "AI安全拦截: 非法SQL语句 - " + normalized); } } }

容错与人机协同

基于 Redis 实现盘点工作流持久化与状态快照，支持任务中断恢复、人工介入纠错与复盘循环迭代，兼顾 AI 自动化与业务灵活性。

  • 工作流持久化：盘点工作流每个节点的状态快照持久化到 Redis，包括输入数据、执行结果、决策路径，支持断点续跑
  • 任务中断恢复：系统异常/网络中断/服务重启后，自动从最近快照恢复执行上下文，无需从头开始
  • 人工介入纠错：在复盘决策与人工审核节点，支持人工修正差异归因、调整盘点范围、覆盖AI决策，修正结果自动回写工作流状态
  • 复盘循环迭代：支持"差异超阈值 → 重新盘点 → 再次分析"的循环迭代，直到差异收敛或人工确认接受
🔄 容错与协同机制
状态快照：每个工作流节点执行后自动快照到 Redis，TTL 7天
中断恢复：异常后自动加载最近快照，从断点节点继续执行
人工介入：Human-in-the-Loop 节点挂起等待，支持确认/修正/驳回
复盘迭代：差异率 > 阈值 → 自动触发复盘循环，最多 3 轮迭代
