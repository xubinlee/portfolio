智慧租住SaaS平台

从0到1构建的企业级多租户SaaS平台 — 公寓·酒店·园区·私有化双模部署，千万级设备在线，百万级消息吞吐

角色: 技术主管、核心架构 业务: 公寓 / 酒店 / 园区 / 私有化 状态: 生产运行中

项目概述

作为技术负责人，牵头将传统项目架构升级为企业级 SaaS 平台，从零搭建统一底层技术底座，打造可复用、高扩展的泛租赁业务中台。统一微服务、身份权限、设备协议与运维体系，适配公寓、酒店、园区三大业务，支持公有云 SaaS + 私有化双模部署。

🎯 核心成就指标
  • 支撑 200+ 企业客户 同时在线运营
  • 千万级 IoT 设备同时在线，百万级消息吞吐/秒
  • 系统可用性达到 99.9%+
  • 满足等保三级安全合规要求

0-1 微服务架构搭建

  • Nacos 服务发现 + 多环境配置隔离：基于 Nacos 实现服务注册发现与配置中心，支持 dev/test/uat/prod 多环境配置隔离，配置热加载无需重启服务
  • Spring Cloud Gateway 统一网关：统一入口路由 + Redis 令牌桶实现租户级/IP级双重限流，保障多租户场景下流量公平分配与系统稳定性
  • Feign 声明式调用：@NoToken 内部免认证 + 自动透传租户/Token 上下文，简化服务间调用链路，避免认证信息丢失
// Feign 租户上下文透传拦截器 @Component public class TenantFeignInterceptor implements RequestInterceptor { @Override public void apply(RequestTemplate template) { String tenantId = TenantContext.getCurrentTenant(); String token = SecurityContextHolder.getContext() .getAuthentication().getCredentials().toString(); if (StrUtil.isNotBlank(tenantId)) { template.header(SecurityConstants.TENANT_HEADER, tenantId); } if (StrUtil.isNotBlank(token)) { template.header(HttpHeaders.AUTHORIZATION, SecurityConstants.BEARER + token); } } }

南北向流量治理与全链路削峰填谷

  • LVS + Keepalived 四层TCP分流：前端流量经 LVS 做四层负载均衡，Keepalived 实现主备高可用切换，单点故障自动转移时间 < 3s
  • 七层 HTTP/WS 路由负载均衡：Nginx 做七层反向代理与 SSL 终结，支持 WebSocket 长连接路由，适配 IoT 设备 MQTT over WebSocket 接入
  • 三层削峰架构：EMQX 共享订阅 → Kafka 分区批量消费 → Redis 窗口聚合去重，构建从设备接入到业务处理的全链路削峰体系，支撑千万级设备同时在线、百万级消息吞吐量
📊 三层削峰架构数据流
第一层 · EMQX 共享订阅：设备 MQTT 消息经 EMQX Broker 接入，共享订阅（Shared Subscription）将消息均匀分发至消费组，避免单点消费瓶颈
第二层 · Kafka 分区批量消费：消息持久化到 Kafka Topic，按租户/设备类型分区，消费者组批量拉取处理，吞吐量提升 10x+
第三层 · Redis 窗口聚合去重：滑动窗口聚合高频上报数据（如传感器遥测），去重后批量写入存储，将写入压力降低 80%+

统一身份认证和权限管理

  • OAuth2 授权服务器：支持密码模式、短信模式、客户端模式三种认证方式，一套认证覆盖用户端 + 设备端 + 管理后台 + 第三方系统四端
  • 自定义 Token 内省器：支持 Bearer Token + API Key 双模式鉴权，适配浏览器/移动端/设备端/第三方对接等不同场景
  • @HasPermission 注解：实现按钮级权限控制，前端菜单 + 后端接口双重校验，杜绝越权访问
  • @Inner 注解 + AOP 切面：实现内部服务调用安全隔离，标注 @Inner 的接口仅允许内部 Feign 调用，外部请求直接拒绝
// @Inner 内部服务调用安全切面 @Aspect @Component public class InnerAuthAspect { @Around("@annotation(innerAuth)") public Object around(ProceedingJoinPoint point, InnerAuth innerAuth) throws Throwable { HttpServletRequest request = WebUtils.getRequest(); String requestHeader = request.getHeader( SecurityConstants.FROM); // 内部调用必须携带 from 标识 if (innerAuth.value() && !SecurityConstants.FROM_IN .equals(requestHeader)) { throw new AccessDeniedException( "内部接口禁止外部访问"); } return point.proceed(); } }

多租户 SaaS 架构

  • MyBatis-Plus TenantLineHandler 插件：SQL 自动注入租户过滤条件，业务代码零侵入，SELECT/INSERT/UPDATE/DELETE 全自动拼接 tenant_id 条件
  • TransmittableThreadLocal 父子线程传递：解决线程池/异步任务中租户上下文丢失问题，确保父子线程租户 ID 自动传递
  • TenantBroker 租户切换器：安全、规范地切换和还原多租户系统中的租户 ID，解决异步任务/定时任务中租户上下文混乱问题
  • DataScope 拦截器：实现行级数据权限隔离，支持全部/本部门/本部门及下级/仅本人等多级数据范围控制
// TenantBroker 安全切换租户上下文 public class TenantBroker { public static <T> T runAs(Integer tenantId, Supplier<T> supplier) { Integer oldTenantId = TenantContext.getCurrentTenant(); try { TenantContext.setCurrentTenant(tenantId); return supplier.get(); } finally { TenantContext.setCurrentTenant(oldTenantId); } } // 异步任务中安全传递租户上下文 public static Runnable wrap(Runnable runnable) { Integer tenantId = TenantContext.getCurrentTenant(); return () -> { try { TenantContext.setCurrentTenant(tenantId); runnable.run(); } finally { TenantContext.clear(); } }; } }

标准化第三方集成

  • 统一 API 接入规范：制定第三方系统接入标准，Gateway 层统一鉴权限流，降低对接成本与安全风险
  • 策略模式 + 工厂模式封装门锁协议差异：不同品牌智能门锁（蓝牙/WiFi/NB-IoT/Zigbee）协议差异通过策略模式透明化，业务层无需感知底层协议
  • MQTT 异步下发指令：设备控制指令经 MQTT 异步下发，支持 QoS 分级保障，关键指令（开锁/报警）走 QoS 2 确保送达
  • Redis 缓存临时密码 + 过期自动清理：一次性密码/限时密码缓存到 Redis 并设置 TTL，过期自动清理，兼顾安全与便捷
// 门锁协议策略工厂 @Component public class LockProtocolFactory { private final Map<String, LockProtocol> protocolMap; public LockProtocolFactory(List<LockProtocol> protocols) { this.protocolMap = protocols.stream() .collect(Collectors.toMap( p -> p.getClass().getAnnotation(LockType.class) .value(), Function.identity())); } public LockProtocol getProtocol(String lockType) { LockProtocol protocol = protocolMap.get(lockType); Assert.notNull(protocol, "不支持的门锁类型: " + lockType); return protocol; } }

公有云 SaaS + 私有化双模部署

  • 自研一键私有化部署方案：Shell + Docker Compose 编排，Harbor 镜像管理 + Rancher 集群管理，支持离线部署包一键导入
  • 屏蔽技术门槛：将环境配置、镜像部署、服务启停等技术操作封装为一键脚本，解决传统模式下技术人员无法常驻现场、实施人员不会部署的行业痛点
  • 适配政企客户场景：支持无外网环境离线部署、高安全等级内网隔离部署，满足等保三级合规要求
🏗️ 双模部署架构
公有云 SaaS 模式：多租户共享资源池，按需付费，自动扩缩容，适合中小客户快速接入
私有化部署模式：独立环境部署，数据完全隔离，支持离线部署包导入，适合政企/大型客户高安全场景

两种模式共享同一套业务代码，通过配置开关切换部署模式，降低维护成本

Jenkins Pipeline CI/CD

  • 全链路自动化：Git Push → Maven 编译 → JaCoCo 覆盖率检测 → SonarQube 质量门禁（阻断 Bug/漏洞）→ Docker 镜像构建 → Harbor 推送 → Rancher 滚动升级
  • 质量门禁：SonarQube 扫描发现 Bug/漏洞时自动阻断发布流程，确保生产环境代码质量
  • 滚动升级：Rancher 滚动升级策略，零停机发布，支持一键回滚

代码质量管控

  • 单元测试嵌入发布流程：JaCoCo 覆盖率检测作为 CI 流水线必经阶段，覆盖率不达标自动阻断
  • 代码规范与安全检测：SonarQube 静态分析 + 代码规范检查 + 安全漏洞扫描，前后端分层全覆盖测试
  • Jest 前端测试：前端单元测试 + 组件测试，确保 UI 层代码质量
  • JaCoCo 覆盖率管控：Java 代码行覆盖率 > 60%，分支覆盖率 > 50%，核心模块覆盖率 > 80%

运维与监控

  • SkyWalking 全链路追踪：分布式链路追踪 + 服务拓扑图 + 慢接口告警，毫秒级定位性能瓶颈
  • ELK 日志检索：Elasticsearch + Logstash + Kibana 日志采集检索，支持多维度日志分析与异常告警
  • Prometheus 指标监控：基础设施 + 应用层指标采集，Grafana 可视化大屏，支持自定义告警规则
  • 自动化数据备份迁移：开发自动化数据备份与迁移脚本，完成数据容灾，满足等保三级要求，减少人工运维成本
