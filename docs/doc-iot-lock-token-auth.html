🔐 门锁 Token 鉴权认证体系 — 全流程详解

出厂证书烧录 · 挑战-应答激活 · mTLS 双向认证 · OAuth2 Token 鉴权 · MQTT ACL 权限控制 — 从安全芯片到云端服务的端到端认证链路。

⇄ mTLS/证书 ⇄
📡

🔐 证书+私钥 → 安全芯片存储 | 📡 ACL 权限控制 → Topic 级隔离 | ☁️ Redis 多维索引 → TenantBroker 租户隔离

认证体系分为 设备身份层（证书 + 挑战-应答） 和 应用鉴权层（OAuth2 Token） 两个维度，二者通过 deviceId + tenantId 关联。

阶段一：出厂预置证书烧录

步骤 1：PKI 证书体系准备

根CA (Root CA)
  └── 中间CA (Intermediate CA) —— 专门签发设备证书
        ├── 门锁设备证书 (client.crt)  —— CN=<deviceId>, OU=<productModel>
        └── 网关设备证书 (client.crt)  —— CN=<gatewayMac>

证书规格

参数规格
证书标准X.509 v3
密钥算法ECDSA P-256（优先，SE原生支持）或 RSA-2048
签名算法SHA256withECDSA
证书SubjectCN=<deviceId>, OU=<productModel>, O=<tenantId>
证书扩展KeyUsage=digitalSignature, keyAgreement; ExtendedKeyUsage=clientAuth
证书有效期10~20 年（覆盖设备生命周期）
CA证书server-ca.crt，用于验证 Broker 服务端身份

步骤 2：工厂烧录 — 密钥对生成与写入

📌 核心原则
私钥永远不离开安全芯片。签名操作在 SE 内部完成，外部只能传入待签名数据、获取签名结果。
工厂产线工站
  │
  ├── 1. 触发密钥对生成（HSM/安全工站内）
  │      ├── 公钥 → 发送至云端CA申请签发证书
  │      └── 私钥 → 直接写入安全芯片，永不离开芯片
  │
  ├── 2. 云端CA签发设备唯一证书 (client.crt)
  │      └── 证书序列号 = 设备唯一标识
  │
  ├── 3. 证书写入安全芯片
  │      ├── client.crt    → SE/TrustZone 安全存储区
  │      ├── 私钥           → SE 私钥槽位（不可读出，只可签名）
  │      └── server-ca.crt → 根CA证书（验证Broker用）
  │
  └── 4. 产测验证
         └── 设备首次上电，通过 MQTT + mTLS 连接验证证书链有效性

步骤 3：设备信息录入

烧录完成后，记录映射关系并同步至云端：

  • 证书序列号 (serialNumber) ↔ deviceId ↔ MAC地址 ↔ 产品型号 ↔ 证书公钥(PEM)
  • 写入工厂MES系统
  • 同步至云端设备注册表（待激活状态，status=INACTIVE）
⚠️ 关键设计
数据库只存 cert_public_key（公钥），不存 deviceSecret（私钥）。私钥永远不离开安全芯片。

阶段三：云端激活 — 挑战-应答 + 设备绑定

步骤 5：挑战-应答式设备激活

📌 核心原则
私钥永远不离开安全芯片。设备用 SE 内私钥对挑战码签名，云端用存储的公钥验签，证明设备持有私钥。
门锁设备                          云端激活服务 (LockDeviceAuthService)
   │                                      │
   │  ── POST /lock/device/challenge ───► │  ① 请求挑战码
   │     { deviceId: "LOCK-XXXX" }        │
   │                                      │
   │  ◄── { challenge: "a3f8b2..." } ──── │  ② 返回随机挑战码
   │                                      │     Redis存储，5分钟有效
   │                                      │     一次性使用（getAndDelete）
   │                                      │
   │  ── SE内签名（私钥不离开芯片） ──      │
   │     signature = SE.sign(challenge)   │
   │                                      │
   │  ── POST /lock/device/activate ────► │  ③ 提交签名+租户信息
   │     { deviceId, signedChallenge,     │
   │       tenantId }                     │
   │                                      │
   │                               ④ 取出并删除挑战码
   │                               ⑤ 用设备证书公钥验签
   │                               ⑥ 校验设备状态
   │                               ⑦ TenantBroker.applyAs() 执行激活
   │                                      │
   │  ◄── { accessToken, refreshToken,   │  ⑧ 返回完整凭证
   │         mqttUsername, mqttPassword,  │
   │         expiresIn }                  │

挑战码生成与验证

// 生成挑战码
public ChallengeResponse generateChallenge(String deviceId) {
    String challenge = SecureUtil.nonce(32);  // 32字节随机数
    String challengeKey = "lock:device:challenge:" + deviceId;
    redisTemplate.opsForValue().set(challengeKey, challenge, 5, TimeUnit.MINUTES);
    return ChallengeResponse.builder().challenge(challenge).build();
}

// 验证时一次性消费
String challenge = (String) redisTemplate.opsForValue().getAndDelete(challengeKey);
if (StrUtil.isBlank(challenge)) {
    throw new LockSecurityException("挑战码已过期或不存在");
}

签名验证

private boolean verifySignature(String challenge, String signature, String publicKeyPem) {
    Signature sig = Signature.getInstance("SHA256withECDSA");
    X509Certificate cert = readCertificate(publicKeyPem);
    sig.initVerify(cert.getPublicKey());
    sig.update(challenge.getBytes(StandardCharsets.UTF_8));
    return sig.verify(Base64.decode(signature));
}

步骤 6：Token 对生成

设备 Token 生成复用 Spring Authorization Server 的 OAuth2TokenGenerator 体系，而非自定义 JwtUtils：

private TokenPair generateTokenPair(String deviceId, Long tenantId, String productModel) {
    String jti = SecureUtil.nonce(64);       // JWT ID
    String refreshJti = SecureUtil.nonce(64); // Refresh ID

    String accessToken = Jwts.builder()
        .id(jti)
        .subject(deviceId)
        .claim("tenantId", tenantId)
        .claim("productModel", productModel)
        .claim("deviceType", "lock")
        .claim("client_id", "lock-device")
        .claim("active", true)
        .issuedAt(new Date())
        .expiration(new Date(System.currentTimeMillis() + 30 * 86400 * 1000L))
        .signWith(getSigningKey())
        .compact();

    return new TokenPair(accessToken, refreshJti);
}

步骤 7：MQTT 凭证独立生成

📌 核心原则
MQTT 凭证与 accessToken 完全独立，不存在数学关系，避免级联泄露。使用 HMAC-SHA256 替代不安全的 MD5。
private MqttCredentials generateMqttCredentials(String deviceId) {
    String username = deviceId;
    String rawPassword = SecureUtil.nonce(32);     // 随机32字节
    String hmacKey = "lock:mqtt:auth:" + deviceId;
    // HMAC-SHA256（替代不安全的MD5）
    String password = HmacUtils.hmacSha256Hex(hmacKey.getBytes(), rawPassword.getBytes());
    return new MqttCredentials(username, password, rawPassword);
}

步骤 9：TenantBroker 保护租户上下文

// TenantBroker.java
public <T> T applyAs(Long tenant, ApplyAs<Long, T> func) {
    final Long pre = TenantContextHolder.getTenantId();  // 保存当前租户
    try {
        TenantContextHolder.setTenantId(tenant);          // 切换到目标租户
        return func.apply(tenant);                      // 执行操作
    } catch (Exception e) {
        throw new TenantBrokerExceptionWrapper(e.getMessage(), e);
    } finally {
        TenantContextHolder.setTenantId(pre);             // 还原租户
    }
}
📌 为什么必须用 TenantBroker
PigxTenantHandler 会在 SQL 层自动拼接 tenant_id 条件。如果不用 TenantBroker，设备激活写入的 tenant_id 会取到错误的值或 null。

完整认证链路

1. 请求进入 → DelegatingAuthenticationConverter 识别 grant_type
      │
      ├─ password → OAuth2ResourceOwnerPasswordAuthenticationConverter
      ├─ sms      → OAuth2ResourceOwnerSmsAuthenticationConverter
      ├─ refresh_token → PigxOAuth2RefreshTokenAuthenticationConverter
      ├─ client_credentials → OAuth2ClientCredentialsAuthenticationConverter
      └─ authorization_code → OAuth2AuthorizationCodeAuthenticationConverter

2. 对应 Provider 执行认证
      │
      ├─ checkClient(registeredClient)  → 校验客户端是否支持此模式
      ├─ authenticationManager.authenticate() → 调用DaoAuthenticationProvider
      │      └─ PigxDaoAuthenticationProvider.retrieveUser()
      │           ├─ 根据clientId + grantType选择UserDetailsService
      │           ├─ loadUserByUsername() → 返回PigxUser（含tenantId）
      │           └─ TenantContextHolder.setTenantId(pigxUser.getTenantId())
      │
      ├─ 并发控制检查（ONLINE_QUANTITY 配置）
      │
      └─ generatAuthenticationToken() → 生成Token
           ├─ tokenGenerator.generate() → 生成 AccessToken (JWT)
           │    └─ CustomeOAuth2TokenCustomizer.customize() 注入claims
           ├─ 生成 RefreshToken
           └─ authorizationService.save() → 存入Redis

public void customize(OAuth2TokenClaimsContext context) {
    OAuth2TokenClaimsSet.Builder claims = context.getClaims();
    claims.claim(SecurityConstants.DETAILS_LICENSE, SecurityConstants.PIGX_LICENSE);
    claims.claim(SecurityConstants.CLIENT_ID, clientId);
    claims.claim(SecurityConstants.ACTIVE, Boolean.TRUE);

    // 客户端模式不返回具体用户信息
    if (SecurityConstants.CLIENT_CREDENTIALS.equals(...)) return;

    PigxUser pigxUser = (PigxUser) context.getPrincipal().getPrincipal();
    claims.claim(SecurityConstants.DETAILS_USER_ID, pigxUser.getId().toString());
    claims.claim(SecurityConstants.DETAILS_USERNAME, pigxUser.getUsername());
}

Token 内省逻辑

public OAuth2AuthenticatedPrincipal introspect(String token) {
    // API-KEY 前缀检测：sk- 开头走独立处理逻辑
    if (token.startsWith("sk-")) {
        return handleApiKeyToken(token);
    }

    // 1. 查Redis中Token
    OAuth2Authorization oldAuthorization = authorizationService.findByToken(token, OAuth2TokenType.ACCESS_TOKEN);
    if (Objects.isNull(oldAuthorization)) {
        throw new InvalidBearerTokenException(token);
    }

    // 2. 加载用户详情
    UserDetails userDetails = optional.get().loadUserByUser((PigxUser) tokenPrincipal);

    // 3. 检查账号状态
    if (isLocked) throw new InvalidBearerTokenException(token);
    if (isExpired) throw new InvalidBearerTokenException(token);

    // 4. 注入客户端信息
    pigxUser.getAttributes().put(SecurityConstants.CLIENT_ID, oldAuthorization.getRegisteredClientId());
    return pigxUser;
}

msgId 防重机制

public synchronized int getMsgId(String key) {
    int randomInt = RandomUtil.randomInt(0, 255);  // 锁端1字节存储
    String redisKey = MqttConstants.MSG_ID_KEY + key;
    if (redisTemplate.opsForSet().size(redisKey) >= 255) {
        redisTemplate.opsForSet().pop(redisKey, 256);   // 255个用完则清空重用
    }
    while (redisTemplate.opsForSet().isMember(redisKey, randomInt)) {
        randomInt = RandomUtil.randomInt(0, 255);   // 确保不重复
    }
    redisTemplate.opsForSet().add(redisKey, randomInt);
    redisTemplate.expire(redisKey, 3, TimeUnit.MINUTES);
    return randomInt;
}

步骤 16：设备 Token 刷新

public LockToken refreshToken(String deviceId, String refreshToken) {
    String refreshKey = "lock:device:token:refresh::" + deviceId;

    if (LOCK.tryLock()) {                              // ReentrantLock 双重检查锁
        try {
            String storedRefresh = (String) redisTemplate.opsForValue().get(refreshKey);
            if (!StrUtil.equals(storedRefresh, refreshToken)) {
                throw new LockSecurityException("刷新令牌无效");
            }
            LockDevice device = lockDeviceMapper.selectByDeviceId(deviceId);
            TokenPair tokenPair = generateTokenPair(deviceId, device.getTenantId(), device.getProductModel());
            MqttCredentials mqttCreds = generateMqttCredentials(deviceId);
            saveDeviceTokenToRedis(deviceId, device.getTenantId(), tokenPair, mqttCreds);
            return LockToken.builder()
                .accessToken(tokenPair.accessToken())
                .refreshToken(tokenPair.refreshToken())
                .mqttUsername(mqttCreds.username())
                .mqttPassword(mqttCreds.password())
                .expiresIn(30 * 86400L)
                .build();
        } finally {
            LOCK.unlock();
        }
    }
    throw new LockSecurityException("系统繁忙，请稍后重试");
}

步骤 17：用户登出 — 批量清除 Token

// 批量删除该用户在所有租户下的全部token
private void removeTokensByUsername(String username) {
    // Redis key 格式：token::username::{username}::{clientId}::{tenantId}::{tokenId}
    Set<String> keys = RedisUtils.keys("token::username::" + username + "*");
    for (String keyName : keys) {
        String[] parts = keyName.split("::");
        if (parts.length < 6) continue;
        String tokenValue = parts[5];
        OAuth2Authorization authorization = authorizationService.findByToken(tokenValue, OAuth2TokenType.ACCESS_TOKEN);
        if (authorization == null) continue;
        Cache userCache = cacheManager.getCache(CacheConstants.USER_DETAILS);
        if (userCache != null) userCache.evict(authorization.getPrincipalName());
        authorizationService.remove(authorization);
    }
}

步骤 19：暴力破解防护

private void recordLoginFailureTimes(String username) {
    String key = String.format("%s%s:%s", CacheConstants.GLOBALLY, CacheConstants.LOGIN_ERROR_TIMES, username);
    Long deltaTimes = ParamResolver.getLong("LOGIN_ERROR_TIMES", 5L);

    if (!isLoginFailureLockEnabled(deltaTimes)) {
        RedisUtils.delete(key);
        return;
    }

    Long times = RedisUtils.increment(key, 1L);
    Long deltaTime = ParamResolver.getLong("DELTA_TIME", 1L);
    RedisUtils.expire(key, deltaTime * 3600);

    if (deltaTimes <= times) {
        userService.lockUser(username);  // 超过阈值，锁定用户
    }
}
