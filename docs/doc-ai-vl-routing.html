🔀 多智能体VL路由架构

深入解析 AgentScope-Claw 框架中多智能体视觉语言（VL）路由的工程实现：两阶段分类+直接调用模式，解决 Subagent 图片传递与自动路由的核心难题。

🔀 多智能体VL路由概述 核心问题

在智能门锁猫眼场景中，多个视觉分析 Subagent（如人形检测、儿童守护）共享同一摄像头输入，但各自拥有不同的系统提示词和分析逻辑。核心挑战在于：当用户上传图片选择"auto"时，如何让系统自动判断应该调用哪个 Subagent，并确保图片被正确传递？

🧩 多Subagent共存 vl-human-detect + vl-child-guard 共享同一图片输入
🎯 智能路由 auto模式根据图片内容自动选择最合适的Subagent
🖼️ 图片穿透 解决sessions_spawn只能传文本、无法传图片的架构限制
⚡ 直接调用 绕过sessions_spawn，通过SessionAgentManager直接传递多模态消息
🔄 三级查找 AgentFactories → hasAgent → Workspace声明文件逐级发现Subagent
🛡️ 降级容错 注册失败自动降级到Gateway路由模式
💡 核心洞察：传统的单阶段路由（顶层Agent看图片→sessions_spawn委托）存在致命缺陷——sessions_spawn工具只接受文本参数，无法将图片转发给Subagent，导致Subagent"看不见"图片，最终顶层Agent只能自己做分析。两阶段路由将"分类决策"与"图片传递"解耦，彻底解决了这个问题。

🔍 问题分析：为什么单阶段路由失败 根因定位

在最初的实现中，auto模式采用单阶段路由：将图片+路由指令一起发给顶层Agent，期望它通过sessions_spawn委托给Subagent。但实际运行中出现了严重问题。

❌ 单阶段路由的执行流程
1 👤 用户上传图片，选择auto
2 📨 ChatController将图片+文本发给顶层Agent(claw)
3 🧠 claw看到图片，决定调用vl-human-detect
4 🔧 claw调用sessions_spawn(agent_id="vl-human-detect", task="分析图片...")
⚠️ 致命缺陷：sessions_spawn的task参数是纯文本，无法传递图片。Subagent收到的是一段文字描述（如"分析这张夜间监控图片"），而非图片本身。这导致：
  • Subagent无法看到图片，只能基于文本猜测
  • 分析结果质量极差，无法完成专业视觉任务
  • 顶层Agent发现Subagent结果不佳，最终自己做分析，绕过了Subagent

✅ 两阶段路由方案 核心方案

两阶段路由将"分类决策"与"图片传递"解耦为两个独立阶段，彻底解决了图片穿透问题。

阶段1：分类 — 顶层Agent看图片，只返回Subagent ID
1 📝 构建分类提示词（可用Subagent列表+分类规则）
2 🖼️ 将分类提示词+图片合并为多模态消息
3 🧠 顶层Agent看图片，判断应使用哪个Subagent
4 🏷️ Agent只返回Subagent ID（如"vl-human-detect"）
阶段2：直接调用 — 绕过sessions_spawn，图片直接传给Subagent
5 🔍 从响应中解析Subagent ID
6 📋 registerSession注册Subagent会话
7 🖼️ createAgent + agent.call(多模态消息) 直接传递图片
8 ✅ Subagent看到真实图片，完成专业分析
✅ 关键优势：阶段1只做分类（轻量级，LLM只需返回一个ID），阶段2通过invokeSubagentViaSession直接调用Subagent并传递多模态消息。Subagent收到的是真实图片，而非文本描述，分析质量得到根本保障。

核心代码实现

// ChatController.java — 两阶段自动路由
private Mono<Msg> autoRouteVlSubagent(Msg multimodalMsg, String parentAgentId) {
    // 阶段1：构建分类提示词+图片，让顶层Agent只返回Subagent ID
    String classificationPrompt = buildVlClassificationPrompt();
    List<ContentBlock> classifyContent = new ArrayList<>();
    classifyContent.add(TextBlock.builder().text(classificationPrompt).build());
    for (var block : multimodalMsg.getContent()) {
        if (block instanceof ImageBlock ib) {
            classifyContent.add(ib);  // 只提取图片块
        }
    }
    Msg classifyMsg = Msg.builder().role(USER).content(classifyContent).build();

    // 发送给顶层Agent进行分类
    RouteResult route = resolveRoute(parentAgentId, "");
    return gateway.run(route.context(), List.of(classifyMsg), route.outboundAddress())
        .flatMap(response -> {
            // 从响应中解析Subagent ID
            String subagentId = extractVlSubagentId(response.getTextContent());
            if (subagentId != null) {
                // 阶段2：直接调用Subagent，传递完整多模态消息（含图片）
                return invokeSubagentViaSession(subagentId, multimodalMsg, parentAgentId);
            }
            // 降级：如果无法分类，返回顶层Agent的直接响应
            return Mono.just(response);
        });
}
📝 分类提示词工程 提示词设计

分类提示词是两阶段路由的关键。它必须让LLM只做分类、不做分析、不调用工具，精确返回Subagent ID。

[VL图片分类任务]
请查看这张图片，判断应该使用哪个subagent来分析。

可用的VL subagent：
- vl-child-guard：儿童离家安全守护系统
- vl-human-detect：门前AI人形检测与行为分析系统

分类规则：
1. 图片中有儿童（身高较矮、体型较小）独自出门、离开家门 → vl-child-guard
2. 其他人员场景（成年人在门前、访客、陌生人徘徊等） → vl-human-detect

重要：只回复subagent的ID（vl-child-guard 或 vl-human-detect），
不要做图片分析，不要使用sessions_spawn或其他工具。
🎯 提示词设计要点：
  • 约束输出格式：明确要求"只回复Subagent ID"，避免LLM做完整分析
  • 禁止工具调用：明确禁止使用sessions_spawn，防止LLM走回单阶段路由的老路
  • 动态Subagent列表：从AgentFactories和Workspace声明文件动态获取，支持扩展
  • 明确分类规则：基于图片内容特征（儿童vs成年人）给出清晰的决策边界

⚡ 直接调用机制 核心实现

invokeSubagentViaSession 是两阶段路由的核心执行路径，它绕过sessions_spawn工具，通过SessionAgentManager直接将多模态消息传递给Subagent。

📋 Step 1:
注册会话
sessionAgentManager.registerSession(subagentId, null, parentSessionKey, 0)
✅ 注册成功 → 继续
❌ 注册失败 → 降级 invokeSubagentViaGateway
🏭 Step 2:
创建Agent
RuntimeContext ctx = RuntimeContext.builder().sessionId(reg.sessionId()).build()
Agent agent = sessionAgentManager.delegate().createAgent(subagentId, ctx)
🖼️ Step 3:
直接调用
agent.call(List.of(multimodalMsg)) — 传递多模态消息（含图片）
.doOnNext(reply -> log.info(...))
.doOnError(ex -> log.error(...))

降级机制

当registerSession失败时（如Subagent未注册），系统自动降级到invokeSubagentViaGateway模式，通过Gateway路由让顶层Agent使用sessions_spawn委托任务。虽然此模式下图片无法传递，但保证了系统可用性。

// 降级路径：通过Gateway让顶层Agent用sessions_spawn委托
private Mono<Msg> invokeSubagentViaGateway(String subagentId, Msg multimodalMsg, String parentAgentId) {
    String spawnInstruction = "请使用 sessions_spawn 工具调用 subagent: " + subagentId;
    Msg spawnMsg = Msg.builder().role(USER).textContent(spawnInstruction).build();
    Msg imageMsg = Msg.builder().role(USER)
        .content(TextBlock.builder().text("以下是用户上传的图片，请转发给 " + subagentId + " 处理：").build())
        .content(multimodalMsg.getContent().stream()
            .filter(b -> b instanceof ImageBlock)
            .map(b -> (ImageBlock) b)
            .findFirst().orElse(null))
        .build();
    RouteResult route = resolveRoute(parentAgentId, spawnInstruction);
    return gateway.run(route.context(), List.of(spawnMsg, imageMsg), route.outboundAddress());
}
🔎 三级Subagent发现机制 注册与发现

当用户指定scenario（如vl-child-guard）时，系统通过三级查找机制定位Subagent：

级别查找方式数据源说明
Level 1 AgentFactories DefaultAgentManager.getAgentFactories() 启动时从subagents/*.md加载并注册的Subagent工厂
Level 2 hasAgent DefaultAgentManager.hasAgent() 检查AgentManager是否包含指定ID的Agent定义
Level 3 Workspace声明文件 AgentSpecLoader.loadFromFilesystem() 从主Agent工作区的subagents/目录动态加载.md声明文件 
// resolveVlSubagentId — 三级查找
private String resolveVlSubagentId(String scenario) {
    if (scenario == null || scenario.isBlank() || "auto".equalsIgnoreCase(scenario)) {
        return null;  // auto模式 → 两阶段路由
    }

    // Level 1: AgentFactories精确匹配
    var factories = sessionAgentManager.delegate().getAgentFactories();
    if (factories.containsKey(scenario)) return scenario;

    // Level 1: AgentFactories前缀匹配（vl- + scenario）
    String prefixed = "vl-" + scenario;
    if (factories.containsKey(prefixed)) return prefixed;

    // Level 2: hasAgent精确匹配
    if (sessionAgentManager.delegate().hasAgent(scenario)) return scenario;
    if (sessionAgentManager.delegate().hasAgent(prefixed)) return prefixed;

    // Level 3: Workspace声明文件
    String fromWorkspace = resolveVlSubagentFromWorkspace(scenario);
    if (fromWorkspace != null) return fromWorkspace;

    // 未找到 → 降级到auto路由
    return null;
}
📄 Subagent声明文件体系 配置管理

每个Subagent由两个文件定义：声明文件（.md）定义元数据，工作区文件（AGENTS.md）定义系统提示词。

文件结构

~/.agentscope/claw/ ├── agentscope.json ← 主Agent配置 ├── workspace/ │ ├── AGENTS.md ← 主Agent系统提示词 │ └── subagents/ │ ├── vl-child-guard.md ← Subagent声明文件 │ └── vl-human-detect.md ← Subagent声明文件 └── agents/ ├── vl-child-guard/ │ └── workspace/ │ └── AGENTS.md ← 儿童守护系统提示词 └── vl-human-detect/ └── workspace/ └── AGENTS.md ← 人形检测系统提示词

声明文件格式

# vl-child-guard.md
---
name: vl-child-guard
description: 儿童离家安全守护系统
workspace:
  mode: isolated
  path: C:\Users\...\.agentscope\claw\agents\vl-child-guard\workspace
model: Qwen/Qwen3.5-122B-A10B
tools: [read_file, glob_files, grep_files, write_file]
---

// 注意：当workspace.mode=isolated且指定了path时，
// body部分会被忽略，系统提示词需放在独立工作区的AGENTS.md中
⚠️ 重要约束：当Subagent声明文件同时指定了workspace.path和inline body时，body会被忽略。系统会输出警告："Subagent declaration 'vl-child-guard' has both workspace.path and a non-empty body; body will be ignored"。系统提示词必须放在独立工作区的AGENTS.md文件中。

🔍 Subagent ID解析策略 容错设计

LLM的输出不可控，可能返回各种格式的响应。extractVlSubagentId采用多级解析策略，确保从各种格式的响应中正确提取Subagent ID。

private String extractVlSubagentId(String text) {
    if (text == null || text.isBlank()) return null;
    Set<String> vlIds = collectVlSubagentIds();  // 收集所有vl-开头的ID

    // 策略1: 精确匹配（理想情况：LLM只返回ID）
    String trimmed = text.trim();
    if (vlIds.contains(trimmed)) return trimmed;

    // 策略2: 包含匹配（LLM返回了包含ID的文本）
    for (String id : vlIds) {
        if (text.contains(id)) return id;
    }
    return null;
}
💡 容错示例：LLM可能返回"vl-human-detect"（精确）、"应该使用 vl-human-detect 来分析"（包含）、甚至"根据图片内容，我建议使用vl-human-detect"（包含）。两种策略都能正确提取ID。
🛡️ 生产最佳实践 工程经验
  • 分类提示词要简洁明确：只要求LLM返回ID，避免触发完整分析
  • 动态Subagent列表：不要硬编码Subagent ID，从运行时注册表动态获取
  • 降级容错：registerSession失败时自动降级到Gateway路由
  • ID解析容错：支持精确匹配和包含匹配两种策略
  • 日志可观测：每个路由决策点都输出INFO级别日志，便于排查
  • Workspace声明与AGENTS.md分离：声明文件定义元数据，AGENTS.md定义系统提示词，避免body被忽略
  • 前缀匹配兼容：支持child-guard自动匹配vl-child-guard
🏁 总结 核心要点

多智能体VL路由架构的核心挑战在于图片穿透——如何让Subagent"看到"用户上传的图片。两阶段路由方案通过将"分类决策"与"图片传递"解耦，彻底解决了sessions_spawn无法传递多模态消息的架构限制。同时，三级Subagent发现机制和降级容错策略确保了系统的健壮性。
