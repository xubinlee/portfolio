🤖 AI Agent 工程概述 核心概念

AI Agent（智能体） 是以大语言模型（LLM）为大脑，结合感知、规划、记忆与工具调用能力，能够自主完成复杂任务的智能系统。相比传统的对话式 LLM，Agent 具备自主决策、多步推理、工具编排与环境交互四大核心能力，是构建企业级 AI 应用的关键范式。

🧠 LLM 大脑 GPT-4 / Claude / Qwen 等大模型作为推理核心
🎯 目标规划 ReAct / Plan-and-Execute 任务分解与规划
💾 记忆系统 短期上下文 + 长期向量记忆（RAG）
🔧 工具调用 Function Calling / MCP 协议集成外部能力
👁️ 环境感知 多模态输入：文本、图像、语音、结构化数据
🔄 反思迭代 Self-Reflection 自我评估与策略调整
💡 核心理念：Agent = LLM + 规划 + 记忆 + 工具 + 反思。单一 LLM 只能"回答问题"，而 Agent 能够"解决问题"——它将模糊需求拆解为可执行步骤，调用工具与环境交互，并根据反馈迭代优化。
🗺️ Agent 架构设计 分层架构

一个完整的 AI Agent 系统采用分层架构，各层职责清晰、解耦设计。以下为生产级 Agent 的标准架构：

层级组件职责技术选型
感知层Input Parser多模态输入解析与预处理LangChain / LlamaIndex
认知层LLM Core推理、决策、自然语言理解GPT-4o / Claude 3.5 / Qwen2
规划层Planner任务分解、步骤规划、策略选择ReAct / Plan-and-Execute
记忆层Memory短期对话 + 长期向量存储Redis + Milvus / Chroma
工具层Tool Hub外部 API、数据库、代码执行Function Calling / MCP
执行层Executor动作执行与结果回传异步任务队列 / 沙箱
反思层Reflector结果评估、错误纠正、策略优化Self-Reflection / CRITIC
编排层Orchestrator多 Agent 协同与流程控制LangGraph / AutoGen

Agent 工作流程

// Agent 核心执行循环（ReAct 模式）
while (!taskCompleted) {
    // 1. 感知：接收用户输入或环境反馈
    observation = perceive(input)

    // 2. 思考：LLM 推理下一步行动
    thought = llm.reason(observation, memory, tools)

    // 3. 行动：选择并调用工具
    action = planner.selectAction(thought)
    result = executor.execute(action)

    // 4. 记忆：存储中间结果到上下文
    memory.store({ observation, thought, action, result })

    // 5. 反思：评估是否完成或需调整
    if (reflector.shouldStop(result)) {
        taskCompleted = true
    }
}

🔄 ReAct 推理模式 核心范式

ReAct（Reasoning + Acting）是 Agent 最经典的推理范式，交替进行"思考"与"行动"，将复杂任务分解为可执行步骤。

ReAct 提示词模板

# prompts/react_prompt.py

REACT_PROMPT = """你是一个智能助手，使用以下工具完成任务。

可用工具：
{tools}

工具使用格式：
Thought: 我需要思考下一步做什么
Action: 工具名称
Action Input: 工具输入参数
Observation: 工具返回结果
... (重复 Thought/Action/Observation)
Thought: 我已经知道最终答案
Final Answer: 最终回答

任务: {input}
{agent_scratchpad}
"""

ReAct Agent 实现

from langchain.agents import create_react_agent, AgentExecutor
from langchain_openai import ChatOpenAI
from langchain.tools import Tool

# 1. 初始化 LLM
llm = ChatOpenAI(model="gpt-4o", temperature=0)

# 2. 定义工具集
def search_web(query: str) -> str:
    """搜索网络获取最新信息"""
    return web_search(query)

def calculate(expression: str) -> str:
    """执行数学计算"""
    return str(eval(expression))

tools = [
    Tool(name="Search", func=search_web, description="搜索网络信息"),
    Tool(name="Calculator", func=calculate, description="数学计算"),
]

# 3. 创建 ReAct Agent
agent = create_react_agent(llm, tools, REACT_PROMPT)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True, max_iterations=5)

# 4. 执行任务
result = executor.invoke({"input": "2024年GDP排名前十的国家及其总和"})
print(result["output"])
💡 关键参数：max_iterations 控制 Agent 最大迭代次数，防止无限循环；verbose=True 打印思考过程便于调试。生产环境建议设置 early_stopping_method="generate" 优雅终止。
🔌 Function Calling 工具调用 OpenAI 标准

Function Calling 是 OpenAI 提出的标准化工具调用协议，LLM 根据函数描述自动选择并生成调用参数，是 Agent 工具层的核心实现。

工具定义（JSON Schema）

# tools/database_tool.py
from pydantic import BaseModel, Field
from langchain.tools import tool

class QueryDBInput(BaseModel):
    """数据库查询输入参数"""
    table_name: str = Field(description="表名，如 users, orders")
    conditions: str = Field(description="查询条件，SQL WHERE 子句")
    limit: int = Field(default=10, description="返回记录数")

@tool(args_schema=QueryDBInput)
def query_database(table_name: str, conditions: str, limit: int = 10) -> str:
    """查询业务数据库，返回 JSON 格式结果"""
    sql = f"SELECT * FROM {table_name} WHERE {conditions} LIMIT {limit}"
    return db.execute(sql).to_json()

原生 Function Calling 调用

from openai import OpenAI
client = OpenAI()

# 1. 定义函数描述
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "获取指定城市的天气",
        "parameters": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市名"},
                "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
            },
            "required": ["city"]
        }
    }
}]

# 2. 第一次调用：LLM 决定调用哪个函数
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "北京今天多少度？"}],
    tools=tools
)

# 3. 执行函数并回传结果
if response.choices[0].message.tool_calls:
    tool_call = response.choices[0].message.tool_calls[0]
    args = json.loads(tool_call.function.arguments)
    result = get_weather(**args)

    # 4. 第二次调用：LLM 基于结果生成最终回答
    final = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "user", "content": "北京今天多少度？"},
            response.choices[0].message,
            {"role": "tool", "tool_call_id": tool_call.id, "content": str(result)}
        ]
    )
⚠️ 安全警告：工具执行涉及数据库或代码运行时，必须进行参数校验与沙箱隔离。禁止直接执行 LLM 生成的 SQL 或代码，应使用参数化查询与受限执行环境。
🗄️ 记忆系统设计 RAG 检索增强

Agent 的记忆系统分为短期记忆（对话上下文）与长期记忆（向量存储），是处理长任务与个性化交互的关键。

记忆类型存储介质容量用途
短期记忆内存 / Redis有限（Token 限制）当前对话上下文
工作记忆Redis Hash中任务中间状态
长期记忆向量数据库无限历史经验、用户偏好
情景记忆向量 + 时间戳无限特定事件回忆
语义记忆知识图谱无限结构化知识

长期记忆实现（向量存储）

from langchain_chroma import Chroma
from langchain_openai import OpenAIEmbeddings
from langchain.memory import ConversationBufferMemory

# 1. 短期记忆：对话缓冲
short_term = ConversationBufferMemory(
    memory_key="chat_history",
    return_messages=True,
    max_token_limit=2000  # 超出自动摘要
)

# 2. 长期记忆：向量数据库
embeddings = OpenAIEmbeddings(model="text-embedding-3-small")
vector_store = Chroma(
    collection_name="agent_memory",
    embedding_function=embeddings,
    persist_directory="./chroma_db"
)

# 3. 存储经验
def save_experience(content: str, metadata: dict):
    """将重要经验存入长期记忆"""
    vector_store.add_texts(
        texts=[content],
        metadatas=[metadata],
        ids=[str(uuid4())]
    )

# 4. 检索相关记忆
def recall_memory(query: str, k: int = 3):
    """检索与当前任务相关的历史经验"""
    docs = vector_store.similarity_search(query, k=k)
    return [f"[{d.metadata}]: {d.page_content}" for d in docs]
💡 优化技巧：长期记忆应结合"时间衰减"权重，近期经验优先召回。可使用 metadata 存储时间戳、任务类型等标签，实现多维度过滤检索。
👥 多 Agent 协同 LangGraph 编排

复杂任务需要多个专业 Agent 协同完成。LangGraph 基于图结构编排 Agent 工作流，支持条件分支、循环与人工介入。

多 Agent 协作模式

协作模式说明适用场景
层级式主 Agent 分配子任务给下属复杂任务分解
顺序式Agent 依次处理，传递结果流水线作业
并行式多 Agent 同时执行不同子任务加速处理
辩论式多 Agent 观点对抗与融合决策优化
竞争式多 Agent 提交方案，择优创意生成

LangGraph 多 Agent 编排

from langgraph.graph import StateGraph, END
from typing import TypedDict, Annotated
import operator

# 1. 定义共享状态
class AgentState(TypedDict):
    task: str
    plan: str
    results: Annotated[list, operator.add]
    final_answer: str

# 2. 定义各 Agent 节点
def planner_node(state: AgentState):
    """规划 Agent：分解任务"""
    plan = planner_llm.invoke(state["task"])
    return {"plan": plan}

def researcher_node(state: AgentState):
    """研究 Agent：信息检索"""
    result = researcher.run(state["plan"])
    return {"results": [result]}

def writer_node(state: AgentState):
    """写作 Agent：生成报告"""
    answer = writer.run(state["results"])
    return {"final_answer": answer}

def should_continue(state: AgentState):
    """条件路由：判断是否需要更多研究"""
    if len(state["results"]) < 3:
        return "researcher"
    return "writer"

# 3. 构建工作流图
workflow = StateGraph(AgentState)
workflow.add_node("planner", planner_node)
workflow.add_node("researcher", researcher_node)
workflow.add_node("writer", writer_node)

workflow.set_entry_point("planner")
workflow.add_edge("planner", "researcher")
workflow.add_conditional_edges("researcher", should_continue)
workflow.add_edge("writer", END)

# 4. 编译并执行
app = workflow.compile()
result = app.invoke({"task": "撰写2024年AI行业分析报告"})
📊 MCP 协议集成 Model Context Protocol

MCP（Model Context Protocol）是 Anthropic 提出的开放协议，标准化 LLM 与外部工具/数据源的连接方式，实现"一次集成，处处可用"。

MCP 架构组件

组件角色说明
MCP Host宿主应用如 Claude Desktop、IDE 插件
MCP Client协议客户端连接 Server 并转发请求
MCP Server能力提供方暴露工具、资源、提示词
Transport传输层stdio / SSE / WebSocket

MCP Server 实现

# mcp_server.py - 自定义 MCP 服务器
from mcp.server import Server
from mcp.types import Tool, TextContent

server = Server("custom-tools")

@server.list_tools()
async def list_tools() -> list[Tool]:
    return [
        Tool(
            name="query_inventory",
            description="查询库存系统商品信息",
            inputSchema={
                "type": "object",
                "properties": {
                    "sku": {"type": "string", "description": "商品SKU"}
                },
                "required": ["sku"]
            }
        )
    ]

@server.call_tool()
async def call_tool(name: str, arguments: dict) -> list[TextContent]:
    if name == "query_inventory":
        result = await fetch_inventory(arguments["sku"])
        return [TextContent(type="text", text=str(result))]

if __name__ == "__main__":
    import mcp.server.stdio
    async def main():
        async with mcp.server.stdio.stdio_server() as (r, w):
            await server.run(r, w, server.create_initialization_options())
    asyncio.run(main())
💡 MCP 优势：相比私有 Function Calling，MCP 实现了工具的"即插即用"——同一 Server 可被 Claude、Cursor、Windsurf 等所有支持 MCP 的客户端复用，大幅降低集成成本。

# 3. 自定义评估器
from langsmith.evaluation import RunEvaluator

class TaskSuccessEvaluator(RunEvaluator):
    def evaluate_run(self, run, example):
        # 检查是否达成任务目标
        output = run.outputs.get("output", "")
        expected = example.outputs.get("expected", "")
        score = 1.0 if expected in output else 0.0
        return {"key": "task_success", "score": score}

# 4. 批量评估数据集
client = Client()
dataset_name = "agent-test-cases"
client.run_on_dataset(
    dataset_name=dataset_name,
    llm_or_chain_factory=agent_executor,
    evaluation=RunEvalConfig(
        custom_evaluators=[TaskSuccessEvaluator()],
        evaluators=["criteria"],
        criteria="helpfulness"
    )
)

生产级 Agent 完整模板

from langchain.agents import AgentExecutor
from langchain_openai import ChatOpenAI
from langchain.globals import set_llm_cache
from langchain.cache import RedisCache
from langchain_core.messages import SystemMessage

# 1. 配置缓存降低成本
import redis
set_llm_cache(RedisCache(redis.Redis(host="localhost", port=6379)))

# 2. 分级模型策略
fast_llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)   # 简单任务
smart_llm = ChatOpenAI(model="gpt-4o", temperature=0)       # 复杂推理

# 3. 系统提示词
SYSTEM_PROMPT = SystemMessage(content="""你是一个企业级 AI 助手。
规则：
1. 只使用提供的工具完成任务，禁止编造信息
2. 每次只执行一个动作，等待结果后再决策
3. 遇到错误时，分析原因并调整策略，最多重试 2 次
4. 涉及敏感操作（删除/支付）必须请求用户确认
5. 输出格式：Thought → Action → Observation → Final Answer
""")

# 4. 构建 Agent
agent = create_react_agent(
    llm=smart_llm,
    tools=tool_set,
    prompt=SYSTEM_PROMPT,
    stop_sequence=["Observation:"]
)

executor = AgentExecutor(
    agent=agent,
    tools=tool_set,
    max_iterations=8,
    early_stopping_method="generate",
    handle_parsing_errors=True,
    return_intermediate_steps=True,  # 便于调试
    verbose=False  # 生产环境关闭
)

# 5. 异步执行与超时控制
import asyncio
async def run_agent(task: str):
    try:
        result = await asyncio.wait_for(
            executor.ainvoke({"input": task}),
            timeout=120
        )
        return result
    except asyncio.TimeoutError:
        return {"output": "任务超时，请简化需求"}
    except Exception as e:
        return {"output": f"执行异常: {e}"}
✅ 检查清单：
  • System Prompt 明确角色、规则与输出格式
  • max_iterations 设置合理上限（建议 5-10）
  • 工具执行具备参数校验与沙箱隔离
  • 启用 LLM 缓存降低重复查询成本
  • 分级模型策略：简单任务用小模型
  • 全链路追踪接入 LangSmith / Langfuse
  • 建立回归测试数据集，版本升级前验证
  • 敏感操作需人工确认（Human-in-the-loop）
🏁 总结与展望 核心要点
