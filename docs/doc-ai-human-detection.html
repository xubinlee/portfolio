👁️ 智能门锁猫眼 AI 人形检测 — 提示词工程方案

基于华为/德施曼/小米/萤石/TCL等行业竞品对标，结合OpenAI/Microsoft视觉提示词工程最佳实践，设计覆盖"人形检测→行为分类→告警决策→多帧时序分析"全链路的完整可落地提示词方案。

方案概述

智能门锁猫眼摄像头抓拍门前图像后，需要通过AI视觉模型进行精准的人形检测与行为分类，在保障居家安全的同时严格保护隐私，将误报率降至最低。本方案基于行业竞品能力对标与提示词工程最佳实践，设计了一套完整可落地的提示词体系。

四层检测流程设计

第一层：人形存在性检测 → 第二层：人形属性描述 → 第三层：行为分类 → 第四层：告警决策

第一层：人形存在性检测

  • 判断画面中是否存在人形生物（完整人体或可见躯干/肢体）
  • 区分"确定是人形"与"疑似人形"与"非人形"
  • 非人形对象包括：宠物、快递包裹、拖把、衣架、门垫、树影晃动、昆虫贴镜头、光线变化、雨滴/雪片

第二层：人形属性描述（仅限可见非敏感特征）

  • 人数：画面中的人形数量
  • 位置：相对于门中心的方位（正前方/偏左/偏右/边缘）
  • 距离估算：门前近距离(0-0.5m) / 门前中距离(0.5-2m) / 门前远距离(2-5m) / 远处(5m+)
  • 可见部位：全身可见 / 上半身可见 / 仅头部可见 / 仅肢体局部可见
  • 衣着概要：颜色、是否戴帽子、是否背包/持物
  • ⚠️ 严禁推断：身份、姓名、年龄、种族、性别、情绪、意图

第三层：行为分类

行为类型判定条件风险等级
正常经过人形处于移动姿态，位于门前远/中距离，无停留迹象无异常
驻足观察人形面向门、姿态静止、距离门前中/近距离低级提示
疑似逗留人形在门前停留（单帧无法确定时长，标记供多帧模块判定）中级告警
可疑贴近人形极近距离(0-0.5m)、面部朝向猫眼/门锁区域、手部接近门体高级告警

第四层：告警决策

告警级别触发条件推送方式
⚪ 无告警无人形 / 正常经过—
🟢 低级提示驻足观察记录但不推送
🟡 中级告警疑似逗留推送APP消息
🔴 高级告警可疑贴近推送APP消息+本地声光提醒

关键约束

误报抑制

⚠️ 以下场景必须判定为"非人形"或"无异常"，不得触发告警：
  • 宠物（猫/狗）经过门前
  • 快递员放下包裹后迅速离开
  • 业主本人回家（配合人脸识别模块联动判定）
  • 光线突变导致的画面整体亮度变化
  • 树影/窗帘/旗帜等非刚性物体晃动
  • 雨雪天气中的雨滴/雪花/水渍
  • 昆虫/蜘蛛贴附镜头

隐私保护

🔐 隐私保护约束：
  • 输出中不得包含任何可用于识别个人身份的信息
  • 对检测到的人脸区域，输出中标注"需脱敏处理"，由下游模块执行模糊化/打码
  • 不输出原始图像的像素级描述

置信度要求

  • 人形置信度 < 0.65 → 判定为"疑似人形"，不触发告警
  • 行为分类置信度 < 0.50 → 降级为"不确定"，输出保守结果
  • 夜间红外模式下，降低人形检测下限至0.55

Few-Shot 示例

示例1：正常经过（无告警）

输入：门前2米处一人形侧身快速经过，方向为从左向右
推理链：人形侧身快速经过→无停留迹象→正常经过→无告警
输出：behavior_analysis.primary_behavior: "正常经过" | alert_level: "none"

示例2：可疑贴近（高级告警）

输入：一人形极近距离面对门，手部抬起靠近门锁区域
推理链：极近距离+手部接近门锁→可疑贴近→高级告警
输出：behavior_analysis.primary_behavior: "可疑贴近" | alert_level: "high" | should_local_alarm: true

示例3：非人形误报抑制（无告警）

输入：夜间红外模式下，一只猫经过门前
推理链：非人形生物(四足,体型不符)→无人形→不触发告警
输出：has_human: false | alert_level: "none"

示例4：夜间疑似逗留（中级告警）

输入：夜间红外模式，一人形在门前1米处静止站立面向门
推理链：夜间+静止站立+面向门→疑似逗留→中级告警
输出：primary_behavior: "疑似逗留" | alert_level: "medium" | should_push_notification: true

多帧时序分析补充提示词

单帧检测模块的连续输出送入时序行为分析模块，进行逗留与徘徊的时序判定：

逗留判定

  • 同一人形在门前中/近距离持续出现 ≥ 30秒 → 确认逗留
  • 逗留时长 30-120秒 → 中级告警
  • 逗留时长 > 120秒 → 高级告警

徘徊判定

  • 同一人形在门前区域反复出现且消失 ≥ 3次，总时长 ≥ 60秒 → 确认徘徊
  • 徘徊行为 → 高级告警（徘徊通常预示踩点风险）

去重与关联

  • 使用位置+衣着+距离特征进行跨帧人形关联
  • 超过30秒未出现同一特征人形 → 视为不同个体

落地部署建议

环节建议方案
模型选型端侧YOLOv8-nano/small做人形检测backbone，VLM(如Qwen2-VL-7B/GPT-4o-mini)做行为语义分析
推理流水线YOLO人形检测 → 裁剪人形区域 → VLM行为语义分析 → 规则引擎告警决策 → 隐私脱敏 → 推送
误报优化建立门前场景专属测试集(含宠物/快递/雨雪/逆光等负例)，持续微调；参考小米动态学习引擎
隐私合规参考德施曼方案，人形检测后立即对人脸区域执行模糊化/打码，再上传云端
功耗控制参考德施曼24G雷达方案，先用低功耗雷达唤醒猫眼，再启动AI推理
分级推送低级仅本地记录；中级推送APP；高级APP推送+本地声光+可选电话通知
多帧模块单帧VLM输出送入轻量级时序状态机(非LLM)，用规则引擎完成逗留/徘徊判定
