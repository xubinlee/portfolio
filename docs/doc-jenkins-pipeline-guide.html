📊 Jenkins Pipeline 概述 核心概念

Jenkins Pipeline 是 Jenkins 2.0 引入的核心特性，它将软件交付流程（持续集成/持续交付）以代码形式定义为 Jenkinsfile，实现了"基础设施即代码"（Infrastructure as Code）的理念。相比传统的自由风格（FreeStyle）作业，Pipeline 具备可版本化、可重入、可视化、支持并发与暂停等优势。

📦 代码化流水线 Jenkinsfile 纳入 Git 版本控制，团队共享与审计
⏱️ 支持暂停与恢复 流水线可在任意阶段暂停，人工确认后继续执行
🔄 并发执行 多阶段并行执行，缩短构建时间
📊 可视化阶段 Blue Ocean 可视化界面直观展示执行进度
🌐 复用性 共享库（Shared Library）实现流水线逻辑跨项目复用
🛡️ 容错与恢复 失败时自动回滚，保障生产稳定
🖥️ Jenkins 环境搭建 安装与配置

推荐采用 Docker 方式部署 Jenkins，便于版本升级与环境隔离。以下为生产环境部署步骤：

# 1. 创建数据卷目录
mkdir -p /data/jenkins/home /data/jenkins/data

# 2. 启动 Jenkins 容器（LTS 长期支持版本）
docker run -d \
  --name jenkins \
  --restart=always \
  -p 8080:8080 -p 50000:50000 \
  -v /data/jenkins/home:/var/jenkins_home \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v $(which docker):/usr/bin/docker \
  -u root \
  jenkins/jenkins:lts-jdk17

# 3. 获取初始密码
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword

# 4. 浏览器访问 http://<server-ip>:8080 完成初始化
⚠️ 重点提示：挂载 /var/run/docker.sock 允许 Jenkins 在容器内调用宿主机 Docker，这是 DinD（Docker in Docker）的替代方案，避免了嵌套容器的安全风险。生产环境建议限制该 socket 的访问权限。

🧊 核心概念与术语 6 大概念

理解 Pipeline 的核心概念是编写高质量流水线的基础。以下为关键术语详解：

概念说明示例
Pipeline整个交付流程的顶层定义，包含所有阶段从代码拉取到生产部署的完整链路
Node执行环境节点，可以是 Jenkins Master 或 Agentbuilt-in / agent-01 / k8s-pod
Stage流水线的逻辑阶段，可视化中显示为独立区块Build / Test / Deploy
Step单个任务指令，是流水线的最小执行单元sh 'mvn clean' / echo 'done'
Agent定义流水线或阶段的执行节点分配策略agent any / agent none
Post流水线或阶段结束后的条件化处理块always / success / failure

两种语法模型对比

维度声明式 (Declarative)脚本式 (Scripted)
语法风格结构化、声明式命令式、Groovy 脚本
可读性高，适合团队协作灵活，适合复杂逻辑
输入验证启动时即校验语法运行时才发现错误
重启支持原生支持重启后恢复需额外处理
推荐场景标准化流水线复杂条件分支与循环
💻 声明式流水线语法 推荐方式

声明式流水线是 Jenkins 官方推荐语法，结构清晰、易于维护。以下为完整语法结构示例：

pipeline {
    agent any

    // ===== 全局环境变量 =====
    environment {
        IMAGE_NAME   = "lxb-gateway"
        REGISTRY     = "registry.cn-hangzhou.aliyuncs.com"
        VERSION      = "${env.BUILD_NUMBER}"
        CREDENTIALS  = credentials('docker-registry-cred')
    }

    // ===== 构建参数 =====
    parameters {
        choice(name: 'ENV', choices: ['dev', 'test', 'prod'], description: '部署环境')
        booleanParam(name: 'SKIP_TESTS', defaultValue: false, description: '跳过单元测试')
        string(name: 'BRANCH', defaultValue: 'main', description: '构建分支')
    }

    // ===== 触发器 =====
    triggers {
        cron('H/15 * * * *')
        pollSCM('H/5 * * * *')
    }

    // ===== 选项配置 =====
    options {
        timeout(time: 30, unit: 'MINUTES')
        retry(3)
        disableConcurrentBuilds()
        buildDiscarder(logRotator(numToKeepStr: '10'))
    }

    stages {
        stage('Checkout') {
            steps { checkout scm }
        }
        stage('Build') {
            steps { sh 'mvn clean package -DskipTests' }
        }
        stage('Test') {
            when { expression { !params.SKIP_TESTS } }
            steps {
                sh 'mvn test'
                junit '**/target/surefire-reports/*.xml'
            }
        }
        stage('Deploy') {
            when { branch 'main' }
            steps {
                sh 'docker build -t ${REGISTRY}/${IMAGE_NAME}:${VERSION} .'
                sh 'docker push ${REGISTRY}/${IMAGE_NAME}:${VERSION}'
            }
        }
    }

    post {
        always  { cleanWs() }
        success { echo '构建成功 ✅' }
        failure { emailext subject: '构建失败', to: 'team@company.com' }
    }
}
💡 关键点：credentials('id') 方法会将凭据自动注入为环境变量，用户名后缀 _USR，密码后缀 _PSW，避免在代码中硬编码敏感信息。
⌨️ 脚本式流水线 灵活控制

脚本式流水线基于 Groovy DSL，提供更强的编程能力，适合复杂条件分支与循环场景：

node {
    // 定义阶段标记
    stage('Prepare') {
        def env = input(
            message: '选择部署环境',
            parameters: [choice(name: 'ENV', choices: ['dev','test','prod'])]
        )
        echo "部署到 ${env} 环境"
    }

    // 并行执行
    parallel {
        stage('Backend Build') {
            sh 'mvn clean package'
        }
        stage('Frontend Build') {
            dir('frontend') {
                sh 'npm ci && npm run build'
            }
        }
    }

    // 异常处理
    try {
        stage('Deploy') {
            sh './deploy.sh'
        }
    } catch (Exception e) {
        echo "部署失败: ${e.message}"
        sh './rollback.sh'
        throw e
    } finally {
        cleanWs()
    }
}
📖 共享库 (Shared Library) 代码复用

共享库允许将公共流水线逻辑抽取为独立 Git 仓库，在多个 Jenkins 项目间复用，是大型团队标准化 CI/CD 的关键手段。

目录结构

jenkins-shared-library/
├── vars/
│   ├── standardPipeline.groovy    # 全局变量/函数定义
│   ├── notifyWechat.groovy
│   └── deployK8s.groovy
├── src/
│   └── com/company/               # 面向对象类定义
│       ├── Deployer.groovy
│       └── ConfigLoader.groovy
└── resources/
    └── com/company/
        └── default-config.yaml    # 外部资源文件

vars/standardPipeline.groovy 示例

// 定义可复用的标准流水线函数
def call(Map config = [:]) {
    pipeline {
        agent any
        environment {
            APP_NAME = "${config.appName ?: 'default'}"
            REGISTRY = "${config.registry}"
        }
        stages {
            stage('Build') {
                steps {
                    sh "${config.buildCmd ?: 'mvn clean package'}"
                }
            }
            stage('Deploy') {
                steps {
                    script {
                        deployK8s env.APP_NAME, env.REGISTRY
                    }
                }
            }
        }
        post {
            always { notifyWechat currentBuild.currentResult }
        }
    }
}

在 Jenkinsfile 中引用

// 项目根目录 Jenkinsfile
@Library('jenkins-shared-library@main') _

standardPipeline(
    appName: 'lxb-gateway',
    registry: 'registry.cn-hangzhou.aliyuncs.com',
    buildCmd: 'mvn clean package -pl lxb-gateway -am'
)
💡 最佳实践：共享库使用 @Library('name@version') 锁定版本，避免主分支变更导致所有项目流水线同时受影响。建议采用语义化版本号管理。
🌿 多分支流水线 分支策略

Multibranch Pipeline 自动为每个分支创建独立作业，实现环境隔离与分支级流水线配置。

🗺️ 分支策略设计
分支模式触发流水线部署环境说明
main✅production主分支，触发生产部署
develop✅test开发集成分支
release/*✅staging预发布分支
feature/*✅dev功能开发分支
hotfix/*✅hotfix紧急修复分支

基于分支的条件部署

stages {
    stage('Deploy') {
        steps {
            script {
                def envMap = [
                    'main':     'production',
                    'develop':  'test',
                    'release/': 'staging'
                ]
                def targetEnv = null
                for (entry in envMap) {
                    if (env.BRANCH_NAME == entry.key || env.BRANCH_NAME?.startsWith(entry.key)) {
                        targetEnv = entry.value
                        break
                    }
                }
                if (targetEnv) {
                    echo "部署到 ${targetEnv}"
                    sh "./deploy.sh ${targetEnv}"
                } else {
                    echo '当前分支不触发部署'
                }
            }
        }
    }
}
🔑 凭据管理 安全实践

Jenkins 提供统一的凭据存储，支持用户名密码、密钥、Secret Text、证书等多种类型，避免敏感信息硬编码。

credentials('id')withCredentials([string()])sshUserPrivateKey()file()certificate()
凭据类型使用场景注入方式
Username/PasswordGit 仓库、Docker Registry
Secret TextAPI Token、Webhook URL
SSH KeyGit SSH 免密拉取
Secret FileKubeconfig、证书文件
Certificate双向 TLS 认证

withCredentials 使用示例

stage('Push Image') {
    steps {
        withCredentials([
            usernamePassword(
                credentialsId: 'docker-registry',
                usernameVariable: 'REG_USER',
                passwordVariable: 'REG_PASS'
            ),
            file(credentialsId: 'kubeconfig', variable: 'KUBECONFIG')
        ]) {
            sh '''
                echo "$REG_PASS" | docker login $REGISTRY -u "$REG_USER" --password-stdin
                docker push $REGISTRY/$IMAGE:$VERSION
                kubectl --kubeconfig=$KUBECONFIG set image deployment/$APP $APP=$REGISTRY/$IMAGE:$VERSION
            '''
        }
    }
}
⚠️ 安全警告：切勿在 echo 或日志中输出凭据变量值。Jenkins 会自动掩码凭据内容，但若凭据被拼接进命令字符串可能泄露。建议使用 --password-stdin 方式传递密码。
🔔 通知与集成 实时反馈

构建状态实时通知是 DevOps 协作的关键环节，支持企业微信、钉钉、邮件、Slack 等多种渠道。

企业微信 Webhook 通知

// vars/notifyWechat.groovy
def call(String buildResult) {
    def colorMap = ['SUCCESS': 'info', 'FAILURE': 'danger', 'UNSTABLE': 'warning']
    def color = colorMap[buildResult] ?: 'comment'
    def content = """
        ## 构建通知
        > **项目**: ${env.JOB_NAME}
        > **分支**: ${env.BRANCH_NAME ?: 'main'}
        > **构建号**: #${env.BUILD_NUMBER}
        > **状态**: ${buildResult}
        > **耗时**: ${currentBuild.durationString}
        > **[查看详情](${env.BUILD_URL})**
    """
    sh """
        curl -s 'https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=$WECHAT_KEY' \
          -H 'Content-Type: application/json' \
          -d '{"msgtype":"markdown","markdown":{"content":"${content}"}}'
    """
}

post 块集成通知

post {
    always  { notifyWechat currentBuild.currentResult }
    success { echo '构建成功' }
    failure {
        emailext subject: "构建失败: ${env.JOB_NAME} #${env.BUILD_NUMBER}",
                 body: """<h2>构建失败</h2>
                     <p>项目: ${env.JOB_NAME}</p>
                     <p>详情: <a href="${env.BUILD_URL}">${env.BUILD_URL}</a></p>""",
                 to: 'devops@company.com'
    }
}
🏆 生产最佳实践 经验总结
⏱️ 设置超时与重试 options 中配置 timeout 与 retry，避免构建卡死
🚫 禁用并发构建 disableConcurrentBuilds 防止资源冲突
📦 清理工作空间 post.always 中调用 cleanWs 释放磁盘
📊 日志保留策略 buildDiscarder 限制历史构建数量
🔐 凭据集中管理 所有密钥存入 Credentials Store，禁止硬编码
🐳 Docker Agent 隔离 使用容器化 Agent 保证构建环境一致性

生产级 Jenkinsfile 模板

@Library('shared-lib@v2.1.0') _

pipeline {
    agent {
        kubernetes {
            yaml '''
apiVersion: v1
kind: Pod
spec:
  containers:
  - name: maven
    image: maven:3.9-eclipse-temurin-17
    command: ["sleep", "infinity"]
    resources:
      requests: { cpu: "1", memory: "2Gi" }
      limits:   { cpu: "2", memory: "4Gi" }
  - name: docker
    image: docker:24-dind
    securityContext: { privileged: true }
'''
        }
    }

    options {
        timeout(time: 30, unit: 'MINUTES')
        retry(2)
        disableConcurrentBuilds()
        buildDiscarder(logRotator(numToKeepStr: '20'))
    }

    stages {
        stage('Build') {
            steps {
                container('maven') {
                    sh 'mvn -B clean package -DskipTests'
                }
            }
        }
        stage('Docker Build & Push') {
            steps {
                container('docker') {
                    script {
                        def image = docker.build("${REGISTRY}/${APP}:${VERSION}")
                        docker.withRegistry("https://${REGISTRY}", 'registry-cred') {
                            image.push()
                        }
                    }
                }
            }
        }
    }

    post {
        always { notifyWechat currentBuild.currentResult }
    }
}
✅ 检查清单：
  • Jenkinsfile 已纳入 Git 版本控制
  • 所有敏感信息通过 Credentials 管理
  • 设置了合理的 timeout 与 retry
  • 启用了 buildDiscarder 控制磁盘占用
  • 构建状态通知覆盖 success/failure/unstable
  • 共享库使用语义化版本锁定
  • Agent 资源限制已配置（CPU/Memory）
🏁 总结 核心要点

Jenkins Pipeline 通过代码化定义交付流程，实现了 CI/CD 的标准化、可版本化与可复用。掌握声明式语法、共享库、多分支策略与凭据管理，是构建企业级自动化交付体系的基础。结合 Docker/Kubernetes 动态 Agent，能够实现弹性、隔离、一致的构建环境，为云原生时代的持续交付提供坚实支撑。
