一致性算法：OT vs CRDT

1. OT（Operational Transformation）

OT 是协同编辑的"始祖"算法，Google Docs、腾讯文档、飞书文档均采用此方案。核心思想：操作原子化 + 服务端转换。当两个并发操作冲突时，通过 Transform 函数调整操作参数，使结果一致。

/** OT 核心流程 — 两人同时编辑 "Hello" */
//
// 用户 A：在位置 5 插入 "!"  →  opA = Insert(5, "!")
// 用户 B：在位置 5 插入 "?"  →  opB = Insert(5, "?")
//
// 如果不转换，两人结果不同：
//   A 先应用 opA → "Hello!" → 再应用 opB → "Hello?!"
//   B 先应用 opB → "Hello?" → 再应用 opA → "Hello!?."
//
// OT Transform 函数：当 A 收到 B 的 opB 时，
//   因为 opB 也在位置 5 插入，A 需要把 opB 调整为 Insert(6, "?")
//   结果：A → "Hello!" → "Hello!?"  ✅
//   B 收到 A 的 opA，调整为 Insert(5, "!")
//   结果：B → "Hello?" → "Hello!?"  ✅ 一致！

public class OTTransform {

    /** Insert vs Insert 的 Transform */
    public static Operation transform(Operation opA, Operation opB) {
        if (opA instanceof Insert insA && opB instanceof Insert insB) {
            // 同位置插入：服务端先到的优先（左优先策略）
            if (insA.position == insB.position) {
                // opB 需要右移一位
                return new Insert(insB.position + 1, insB.text);
            }
            // opB 位置在 opA 之后，需要偏移
            if (insB.position > insA.position) {
                return new Insert(insB.position + insA.text.length(), insB.text);
            }
        }
        if (opA instanceof Insert insA && opB instanceof Delete delB) {
            if (insA.position <= delB.position) {
                return new Delete(delB.position + insA.text.length(), delB.length);
            }
            // 插入位置在删除范围内，需要拆分删除操作
            return new Delete(delB.position, delB.length);
        }
        // ... Delete vs Delete, Delete vs Insert 等组合
        return opB;
    }
}

2. CRDT（Conflict-free Replicated Data Type）

CRDT 是近年的新贵，Figma、Notion、Linear 都在用。核心思想：为每个字符分配全局唯一 ID，操作天然可交换，无需中心服务器仲裁。

/** CRDT — RGA（Replicated Growable Array）实现 */
public class RGANode {
    private LamportTimestamp id;     // 全局唯一 ID：clock + clientId
    private Character value;          // 字符值
    private LamportTimestamp leftId;   // 左邻居 ID（插入位置参考）
    private boolean deleted;           // 逻辑删除标记（tombstone）
}

/** Lamport 时间戳 — 因果序保证 */
public class LamportTimestamp implements Comparable<LamportTimestamp> {
    private long clock;       // 逻辑时钟
    private String clientId;  // 客户端唯一标识

    @Override
    public int compareTo(LamportTimestamp other) {
        // 先比较逻辑时钟，再比较 clientId（确定性全序）
        int cmp = Long.compare(this.clock, other.clock);
        return cmp != 0 ? cmp : this.clientId.compareTo(other.clientId);
    }
}

/** CRDT 插入操作 — 无需 Transform */
public class CRDTDocument {
    private List<RGANode> sequence = new ArrayList<>();
    private LamportTimestamp clock = new LamportTimestamp(0, clientId);

    public InsertOp localInsert(int index, char value) {
        clock = clock.increment();
        LamportTimestamp leftId = (index > 0)
            ? sequence.get(index - 1).getId()
            : LamportTimestamp.ROOT;

        RGANode node = new RGANode(clock, value, leftId, false);
        // 本地立即生效（乐观更新）
        insertByLeftId(node);

        return new InsertOp(node);  // 广播给其他客户端
    }

    public void remoteInsert(InsertOp op) {
        // CRDT 天然无冲突：按 ID 偏序插入即可
        // 无需 Transform，无需中心服务器仲裁
        insertByLeftId(op.getNode());
        clock = clock.merge(op.getNode().getId());
    }
}

3. OT vs CRDT 全维度对比

维度OTCRDT
核心思想操作转换，服务端仲裁数据结构自合并，无需仲裁
一致性保证强一致（中心服务器定序）最终一致（数学可证明收敛）
服务端依赖强依赖（必须中心化）弱依赖（支持 P2P）
离线支持差（重连需补发+重排）优（本地操作，上线后合并）
元数据开销低（仅操作本身）高（每字符带 ID + tombstone）
算法复杂度高（Transform 组合爆炸）低（插入/删除独立处理）
典型产品Google Docs、腾讯文档、飞书Figma、Notion、Linear、Yjs
适用场景中心化、强一致、纯文本去中心化、离线优先、结构化数据
选型建议
中心化场景 → OT：强一致要求高、服务端可控、纯文本编辑。去中心化/离线场景 → CRDT：需要离线编辑、P2P 协同、结构化数据（JSON/Map）。混合方案：飞书文档采用"文本用 OT、表格用 CRDT"的混合架构，按数据类型选择最优算法。

系统架构设计

1. 整体分层架构

L1 编辑器内核层 ProseMirror / TipTap / Lexical — 文档模型、渲染、输入捕获 客户端
L2 协同引擎层 OT Client / Yjs CRDT — 本地操作生成、远程操作应用 客户端
L3 通信层 WebSocket / WebRTC — 双向实时通信、连接管理 全链路
L4 协同服务层 Document Hub — 操作排序、Transform、广播、版本管理 服务端
L5 操作日志 + 文档快照 + 元数据 — 持久化与恢复 存储层 服务端

2. Document Hub 核心服务

Document Hub 是协同编辑的"大脑"，负责操作排序、转换、广播和版本管理：

/** Document Hub — 协同编辑中心服务 */
@Service
public class DocumentHubService {

    // 文档房间：每个打开的文档对应一个 Room
    private final ConcurrentHashMap<String, DocumentRoom> rooms = new ConcurrentHashMap<>();

    public void handleOperation(String docId, String userId, ClientOperation clientOp) {
        DocumentRoom room = rooms.computeIfAbsent(docId, DocumentRoom::new);

        // 1. 服务端全局递增版本号
        long serverSeq = room.nextSeq();

        // 2. OT Transform：对齐客户端版本与服务端版本
        ServerOperation serverOp = transformToServerVersion(room, clientOp, serverSeq);

        // 3. 应用到服务端文档模型
        room.applyOperation(serverOp);

        // 4. 持久化操作日志
        opLogStore.append(docId, serverOp);

        // 5. 广播给同文档的其他协作者
        broadcastToPeers(room, userId, serverOp);

        // 6. ACK 回发送者
        sendAck(userId, docId, serverSeq);
    }

    private ServerOperation transformToServerVersion(
            DocumentRoom room, ClientOperation clientOp, long targetSeq) {
        // 客户端基于 baseVersion，服务端已到 currentVersion
        // 需要把 clientOp 依次 transform 过 [baseVersion+1, targetSeq] 的操作
        Operation op = clientOp.getOperation();
        long baseVersion = clientOp.getBaseVersion();

        for (long v = baseVersion + 1; v <= targetSeq; v++) {
            ServerOperation concurrent = room.getOperationAt(v);
            op = OTTransform.transform(concurrent.getOperation(), op);
        }

        return new ServerOperation(targetSeq, op, clientOp.getUserId());
    }
}

WebSocket 实时通信层

1. 连接管理

/** WebSocket 连接管理器 */
@ServerEndpoint(value = "/ws/collab/{docId}", configurator = SpringConfigurator.class)
public class CollabWebSocket {

    // docId → Set  一个文档的多个协作者
    private static final ConcurrentHashMap<String, CopyOnWriteArraySet<Session>> docSessions = new ConcurrentHashMap<>();

    @OnOpen
    public void onOpen(Session session, @PathParam("docId") String docId) {
        // 1. 鉴权：验证 Token
        String token = session.getRequestParameterMap().get("token").get(0);
        UserInfo user = authService.validate(token);
        if (user == null) { session.close(); return; }

        // 2. 权限校验：是否有编辑权限
        if (!permissionService.canEdit(user.getUserId(), docId)) {
            session.close(); return;
        }

        // 3. 加入文档房间
        session.getUserProperties().put("userId", user.getUserId());
        session.getUserProperties().put("docId", docId);
        docSessions.computeIfAbsent(docId, k -> new CopyOnWriteArraySet<>()).add(session);

        // 4. 推送当前文档状态（快照 + 增量 Ops）
        DocumentSnapshot snapshot = snapshotService.getLatest(docId);
        sendJson(session, MessageType.INIT, snapshot);

        // 5. 广播用户加入通知（光标 Presence）
        broadcastPresence(docId, user.getUserId(), "JOIN");
    }

    @OnMessage
    public void onMessage(String message, Session session) {
        CollabMessage msg = JSON.parseObject(message, CollabMessage.class);
        String docId = (String) session.getUserProperties().get("docId");
        String userId = (String) session.getUserProperties().get("userId");

        switch (msg.getType()) {
            case OPERATION -> documentHub.handleOperation(docId, userId, msg.getOp());
            case CURSOR    -> broadcastCursor(docId, userId, msg.getCursor());
            case SELECTION -> broadcastSelection(docId, userId, msg.getSelection());
            case HEARTBEAT -> sendJson(session, MessageType.HEARTBEAT_ACK, "OK");
        }
    }

    @OnClose
    public void onClose(Session session) {
        String docId = (String) session.getUserProperties().get("docId");
        String userId = (String) session.getUserProperties().get("userId");
        docSessions.getOrDefault(docId, new CopyOnWriteArraySet<>()).remove(session);
        broadcastPresence(docId, userId, "LEAVE");
    }
}

2. 高可用：集群化 WebSocket

单机 WebSocket 无法支撑大规模并发，需要集群化部署。核心问题是：同一文档的协作者可能连到不同节点，需要跨节点消息路由。

/** 基于 Redis Pub/Sub 的跨节点消息路由 */
@Service
public class CrossNodeRouter {

    private final RedisTemplate<String, String> redisTemplate;
    private final String nodeId = UUID.randomUUID().toString();

    // 订阅文档频道
    public void subscribe(String docId) {
        String channel = "collab:doc:" + docId;
        redisTemplate.execute((RedisCallback<Void>) conn -> {
            conn.subscribe((message, pattern) -> {
                CollabMessage msg = JSON.parseObject(message, CollabMessage.class);
                // 只处理其他节点发来的消息
                if (!msg.getOriginNode().equals(nodeId)) {
                    localBroadcast(docId, msg);
                }
            }, channel.getBytes());
            return null;
        });
    }

    // 发布到文档频道
    public void publish(String docId, CollabMessage msg) {
        msg.setOriginNode(nodeId);
        redisTemplate.convertAndSend("collab:doc:" + docId, JSON.toJSONString(msg));
    }
}

存储模型：操作日志 + 快照

1. 操作日志（OpLog）

每次编辑操作追加写入操作日志，保证不可变、有序、可重放：

CREATE TABLE doc_op_log (
    id              BIGINT       PRIMARY KEY AUTO_INCREMENT,
    doc_id          VARCHAR(64)  NOT NULL,
    seq             BIGINT       NOT NULL,           -- 服务端全局递增版本号
    user_id         VARCHAR(64)  NOT NULL,
    op_type         VARCHAR(16)  NOT NULL,           -- INSERT / DELETE / RETAIN
    position        INT,                              -- 操作位置
    content         TEXT,                              -- 操作内容
    length          INT,                              -- 删除长度
    base_version    BIGINT       NOT NULL,           -- 客户端基于的版本
    created_at      DATETIME     DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_doc_seq (doc_id, seq),
    KEY idx_doc_created (doc_id, created_at)
);

/** 操作日志追加 — 顺序写入 */
@Repository
public class OpLogStore {

    public void append(String docId, ServerOperation op) {
        // MongoDB 也可以：按 docId 分片，顺序追加写入
        opLogMapper.insert(DocOpLog.builder()
            .docId(docId)
            .seq(op.getSeq())
            .userId(op.getUserId())
            .opType(op.getOperation().getType().name())
            .position(op.getOperation().getPosition())
            .content(op.getOperation().getContent())
            .baseVersion(op.getBaseVersion())
            .build());
    }

    public List<ServerOperation> getOpsAfter(String docId, long sinceSeq) {
        // 客户端重连时，拉取缺失的操作
        return opLogMapper.selectList(new QueryWrapper<DocOpLog>()
            .eq("doc_id", docId)
            .gt("seq", sinceSeq)
            .orderByAsc("seq"));
    }
}

2. 文档快照（Snapshot）

如果只有操作日志，新用户打开文档需要重放全部历史操作，代价极高。定期生成文档快照，新用户只需加载最新快照 + 增量操作：

/** 文档快照服务 */
@Service
public class SnapshotService {

    private static final long SNAPSHOT_INTERVAL_OPS = 500;  // 每 500 次操作生成快照

    public DocumentSnapshot getLatest(String docId) {
        // 1. 尝试从 Redis 缓存获取
        String cacheKey = "doc:snapshot:" + docId;
        DocumentSnapshot cached = redisTemplate.opsForValue().get(cacheKey);
        if (cached != null) return cached;

        // 2. 从对象存储加载最新快照
        DocumentSnapshot snapshot = ossClient.getObject(
            "doc-snapshots", docId + "/latest.json",
            DocumentSnapshot.class
        );

        // 3. 回放快照之后的增量操作
        List<ServerOperation> deltaOps = opLogStore.getOpsAfter(docId, snapshot.getSeq());
        for (ServerOperation op : deltaOps) {
            snapshot.apply(op);
        }

        // 4. 缓存到 Redis
        redisTemplate.opsForValue().set(cacheKey, snapshot, 5, TimeUnit.MINUTES);

        return snapshot;
    }

    /** 异步生成快照 */
    @Async
    public void maybeCreateSnapshot(String docId, long currentSeq) {
        DocumentSnapshot last = snapshotRepo.findLatest(docId);
        if (currentSeq - last.getSeq() >= SNAPSHOT_INTERVAL_OPS) {
            DocumentSnapshot newSnapshot = getLatest(docId);  // 已回放至最新
            ossClient.putObject("doc-snapshots",
                docId + "/" + currentSeq + ".json",
                JSON.toJSONString(newSnapshot));
            // 更新 latest 指针
            ossClient.copyObject("doc-snapshots",
                docId + "/" + currentSeq + ".json",
                docId + "/latest.json");
        }
    }
}
存储分层策略
元数据（MySQL）：docId、owner、权限、创建时间 — 强一致、低频查询。操作日志（MongoDB/TiKV）：高写入、按 docId 顺序追加。文档快照（对象存储 COS/OSS）：JSON/Protobuf 序列化，每 500 次操作生成一次。实时状态（Redis）：当前在线用户、光标位置、临时编辑状态，TTL 10s。

1. 文档权限模型

CREATE TABLE doc_permission (
    id              BIGINT       PRIMARY KEY AUTO_INCREMENT,
    doc_id          VARCHAR(64)  NOT NULL,
    target_type     VARCHAR(16)  NOT NULL,  -- USER / DEPARTMENT / ORG / LINK
    target_id       VARCHAR(64)  NOT NULL,
    role            VARCHAR(16)  NOT NULL,  -- OWNER / EDITOR / COMMENTER / VIEWER
    grant_by        VARCHAR(64)  NOT NULL,
    expire_at       DATETIME,                    -- NULL=永久
    created_at      DATETIME     DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_doc_target (doc_id, target_type, target_id)
);

/** 权限校验服务 */
@Service
public class DocPermissionService {

    public DocRole resolveRole(String userId, String docId) {
        // 1. 查直接用户权限
        DocPermission direct = permRepo.findByDocAndTarget(docId, "USER", userId);
        if (direct != null) return direct.getRole();

        // 2. 查部门权限（用户所属部门）
        List<String> deptIds = userService.getUserDepartments(userId);
        for (String deptId : deptIds) {
            DocPermission dept = permRepo.findByDocAndTarget(docId, "DEPARTMENT", deptId);
            if (dept != null) return dept.getRole();
        }

        // 3. 查组织权限
        String orgId = userService.getUserOrgId(userId);
        DocPermission org = permRepo.findByDocAndTarget(docId, "ORG", orgId);
        if (org != null) return org.getRole();

        // 4. 查链接分享权限
        DocPermission link = permRepo.findByDocAndTarget(docId, "LINK", "*");
        if (link != null) return link.getRole();

        // 5. 无权限
        return DocRole.NONE;
    }
}

离线编辑与冲突合并

1. 离线操作缓冲

用户断网时，本地操作暂存到 IndexedDB，网络恢复后批量同步：

// 客户端离线操作缓冲
class OfflineBuffer {
    private pendingOps: ClientOperation[] = [];
    private db: IDBDatabase;

    async buffer(op: ClientOperation) {
        // 本地立即应用（乐观更新）
        this.editor.applyLocal(op);
        // 暂存到内存 + IndexedDB
        this.pendingOps.push(op);
        await this.db.put("pendingOps", op);
    }

    async flush() {
        if (this.pendingOps.length === 0) return;

        // 合并为批量请求
        const batch: ClientOperation[] = [...this.pendingOps];
        this.pendingOps = [];

        try {
            // 发送到服务端，服务端逐个 Transform 后应用
            const results = await this.ws.sendBatch(batch);
            // 清除 IndexedDB
            await this.db.clear("pendingOps");
        } catch (e) {
            // 发送失败，重新入队
            this.pendingOps.unshift(...batch);
        }
    }
}

2. 重连同步流程

S1 WebSocket 重连 指数退避重连，携带 lastSeq 标识 客户端
S2 拉取增量操作 服务端返回 [lastSeq+1, current] 的操作 服务端
S3 本地 Transform 客户端对暂存操作做 Transform，对齐版本 客户端
S4 批量提交 将离线期间的操作批量发送到服务端 客户端
S5 服务端 Transform 服务端逐个 Transform 后应用，返回新版本号 服务端
CRDT 离线优势
CRDT 天然支持离线编辑：本地操作立即生效，上线后按 ID 偏序自动合并，无需 Transform。代价是元数据体积较大（每字符带 LamportTimestamp），但 Yjs 等框架通过二进制编码将开销压缩到可接受范围。

实时光标与选区同步

除了文档内容同步，协同编辑还需要同步每位用户的光标位置、选区范围、头像信息，让协作者"看到彼此"：

/** Presence Service — 光标/选区广播 */
@Service
public class PresenceService {
    private static final String PRESENCE_KEY = "doc:presence:";

    public void updateCursor(String docId, String userId, CursorPos pos) {
        String key = PRESENCE_KEY + docId;
        redisTemplate.opsForHash().put(key, userId, JSON.toJSONString(
            PresenceInfo.builder().userId(userId).cursorPos(pos)
                .timestamp(System.currentTimeMillis()).build()));
        redisTemplate.expire(key, 10, TimeUnit.SECONDS);
        crossNodeRouter.publish(docId, CollabMessage.cursor(userId, pos));
    }

    public Map<String, PresenceInfo> getOnlineUsers(String docId) {
        Map<Object, Object> entries = redisTemplate.opsForHash()
            .entries(PRESENCE_KEY + docId);
        return entries.entrySet().stream()
            .collect(Collectors.toMap(
                e -> (String) e.getKey(),
                e -> JSON.parseObject((String) e.getValue(), PresenceInfo.class)));
    }
}

性能优化与工程实践

1. 操作压缩

连续的相同类型操作可以合并，减少传输和存储开销：

/** 操作压缩 — 合并连续同类操作 */
public class OpCompressor {
    public List<Operation> compress(List<Operation> ops) {
        if (ops.size() <= 1) return ops;
        List<Operation> result = new ArrayList<>();
        Operation merged = ops.get(0);
        for (int i = 1; i < ops.size(); i++) {
            Operation current = ops.get(i);
            if (merged instanceof Insert mIns && current instanceof Insert cIns
                && mIns.position + mIns.text.length() == cIns.position) {
                merged = new Insert(mIns.position, mIns.text + cIns.text);
            } else if (merged instanceof Delete mDel && current instanceof Delete cDel
                && mDel.position == cDel.position) {
                merged = new Delete(mDel.position, mDel.length + cDel.length);
            } else { result.add(merged); merged = current; }
        }
        result.add(merged);
        return result;
    }
}
