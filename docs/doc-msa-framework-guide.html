MSA Framework 使用手册

微服务通用框架的完整使用指南 — 快速开始、配置说明、API参考、常见问题解答与最佳实践。

框架概述

MSA (MicroService Architecture) Framework 是一套基于 Spring Cloud Alibaba 的企业级微服务基础框架，旨在为业务开发提供开箱即用的基础设施能力，让开发者专注于业务逻辑实现而非重复造轮子。

🎯 设计目标

标准化：统一技术栈与编码规范，降低团队协作成本
组件化：模块化设计，按需引入依赖
可扩展：预留扩展点，支持定制化需求
生产就绪：内置监控、日志、链路追踪等运维能力

模块名称 功能描述 Maven坐标

快速开始

环境要求

  • JDK 17+ 或 JDK 21（推荐）
  • Maven 3.8+
  • Nacos Server 2.x（注册+配置中心）
  • MySQL 8.0+ / PostgreSQL 14+
  • Redis 7.x

项目初始化

# 克隆框架模板
git clone https://gitlab.example.com/hbs4cloud/pigx-template.git my-service

cd my-service

# 修改 pom.xml 中的 artifactId 和 groupId
# 配置 application.yml 连接 Nacos 地址

# 启动服务
mvn spring-boot:run -Dspring-boot.run.profiles=dev

最小化配置示例

# bootstrap.yml
spring:
  application:
    name: my-custom-service
  cloud:
    nacos:
      discovery:
        server-addr: ${NACOS_HOST:127.0.0.1}:8848
        namespace: dev
      config:
        server-addr: ${NACOS_HOST:127.0.0.1}:8848
        namespace: dev
        file-extension: yml
        shared-configs:
          - data-id: common.yml
            group: DEFAULT_GROUP
            refresh: true

核心配置说明

安全认证配置

security:
  oauth2:
    client:
      client-id: my-service
      client-secret: ${OAUTH2_SECRET}
      access-token-uri: http://pigx-auth/oauth/token
    resource:
      token-info-uri: http://pigx-auth/oauth/check_token
    ignore-urls:
      - /actuator/**
      - /v3/api-docs/**

数据源配置

spring:
  datasource:
    type: com.zaxxer.hikari.HikariDataSource
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://${DB_HOST:localhost}:3306/my_db?useUnicode=true&characterEncoding=utf8&zeroDateTimeBehavior=convertToNull&useSSL=true&serverTimezone=GMT%2B8
    username: ${DB_USER:root}
    password: ${DB_PASSWORD}
    hikari:
      minimum-idle: 5
      maximum-pool-size: 20
      idle-timeout: 30000
      connection-timeout: 30000
      max-lifetime: 1800000

⚠️ 安全提醒

生产环境中严禁将数据库密码、OAuth2密钥等敏感信息硬编码到配置文件中！请使用 Nacos 加密配置或 Vault/KMS 等密钥管理方案。框架已集成 Jasypt 加密插件，可通过 ENC() 函数加密敏感字段。

常用 API 参考

统一响应格式 R<T>

方法 说明 示例
R.ok() 成功无数据返回 R.ok()
R.ok(T data) 成功带数据返回 R.ok(userVO)
R.ok(IPage page) 分页查询成功 R.ok(pageResult)
R.failed(String msg) 业务失败 R.failed("参数校验失败")
R.failed(int code, String msg) 自定义错误码 R.failed(40001, "Token过期")

数据权限注解

@DataPermission({
    @DataColumn(key = "dept_name", value = "dept_id"),
    @DataColumn(key = "user_name", value = "user_id")
})
@GetMapping("/list")
public R<IPage<UserVO>> list(Page page, UserQuery query) {
    // 框架自动拼接 SQL WHERE 条件实现数据隔离
    return R.ok(userService.selectUserPage(page, query));
}

常见问题 FAQ

Q1: 服务注册失败怎么办？

A: 检查以下几点：

  1. 确认 Nacos 服务地址和端口正确（默认8848）
  2. 确认 Namespace ID 与 Nacos 控制台一致
  3. 检查防火墙是否开放了 Nacos 端口
  4. 查看日志中的异常堆栈信息

Q2: 如何实现多租户隔离？

A: 框架内置了基于 TenantId 的租户隔离机制：

  • 在请求头中传递 X-Tenant-ID 标识当前租户
  • 通过 Mybatis-Plus TenantLineInnerInterceptor 自动拼接租户条件
  • Redis 缓存 key 前缀自动添加 tenantId 隔离

Q3: 如何添加新的业务模块？

A: 参考以下步骤：

  1. 新建 Maven 子模块 pigx-{module}-biz
  2. 继承 pigx-common-parent 父 POM
  3. 添加所需依赖(common-security/data-scope/log 等)
  4. 编写 Controller → Service → Mapper 标准三层结构
  5. 在 Nacos 中配置独立的 application-{module}.yml
