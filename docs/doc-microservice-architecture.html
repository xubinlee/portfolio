🏗️ 微服务通用底层架构

Spring Boot 4.x + Spring Cloud 2025 + Spring Cloud Alibaba 2025 — 多租户 SaaS · 多语言多币种 · 聚合支付 · 工作流引擎 · 灰度发布 · 幂等性 · 熔断降级全栈微服务底座。

项目概述与技术栈

本项目是一个基于 Spring Boot 4.x + Spring Cloud 2025 + Spring Cloud Alibaba 2025 的全栈微服务底层架构，覆盖从多语言、多币种、多渠道、熔断降级、幂等性、灰度发布等技术中台通用底座。采用 Java 17 微服务架构，支持多租户 SaaS 模式，面向全球多区域运营。

API 网关服务

基于 Spring Cloud Gateway (WebFlux) 的响应式网关，高并发流量入口 + 多端适配：

// 全局请求过滤器 — 清洗内部标识、路径重写
@Component
public class RequestGlobalFilter implements GlobalFilter, Ordered {

    @Override
    public Mono<Void> filter(ServerWebExchange exchange, GatewayFilterChain chain) {
        // 1. 清洗 from 参数，防止外部伪造内部调用标识
        ServerHttpRequest request = exchange.getRequest().mutate()
            .headers(headers -> headers.remove("from"))
            .build();

        // 2. 添加 X-Forwarded-Prefix，支持 Swagger 聚合文档
        String prefix = exchange.getRequest().getHeaders().getFirst("X-Forwarded-Prefix");
        if (StringUtils.hasText(prefix)) {
            request = request.mutate()
                .header("X-Forwarded-Prefix", prefix)
                .build();
        }

        return chain.filter(exchange.mutate().request(request).build());
    }

    @Override
    public int getOrder() { return -1000; }
}
// IP 限流配置 — 应对秒杀/促销高并发
@Configuration
public class RateLimiterConfiguration {

    @Bean("remoteAddrKeyResolver")
    public KeyResolver remoteAddrKeyResolver() {
        return exchange -> Mono.just(
            exchange.getRequest().getRemoteAddress()
                .getAddress().getHostAddress()
        );
    }
}

业界验证优化方案

1. 多租户数据隔离

// 基于 @TenantTable 注解的行级隔离
@TenantTable
@TableName("pay_trade_order")
public class PayTradeOrder { ... }

// MyBatis-Plus 拦截器自动注入 tenant_id 条件
@Component
public class TenantLineInnerInterceptor extends JsqlParserSupport {
    @Override
    protected void processSelectBody(... ) {
        // 自动为 SELECT 语句添加 WHERE tenant_id = ?
        // 自动为 INSERT 语句填充 tenant_id 字段
        // 自动为 UPDATE/DELETE 添加 tenant_id 条件
    }
}
隔离策略对比
共享数据库共享表（当前方案）：tenant_id 行级隔离，成本最低，适合 SaaS 场景。共享数据库独立 Schema：按租户分 Schema，隔离性更好但运维成本高。独立数据库：完全物理隔离，适合金融/政务等强合规场景。

2. 幂等性保障

// 基于 @Idempotent 注解的防重复提交
@Idempotent(key = "#orderId", timeout = 3000)
@PostMapping("/pay/submit")
public R<Void> submitPay(@RequestBody PayRequest request) {
    // 3秒内相同 orderId 的请求只执行一次
    return R.ok(payService.submit(request));
}

// 实现原理：Redis SETNX + 过期时间
// key = idempotent:className:methodName:orderId
// 首次请求 SETNX 成功 → 执行业务 → 返回结果
// 重复请求 SETNX 失败 → 直接返回"请勿重复提交"

3. 灰度发布

4. 分布式事务

// 基于 Seata AT 模式的分布式事务
@GlobalTransactional(timeoutMills = 60000)
public void placeOrder(OrderDTO orderDTO) {
    // 1. 创建订单（订单服务）
    orderService.create(orderDTO);

    // 2. 扣减库存（库存服务）
    inventoryService.deduct(orderDTO.getGoodsId(), orderDTO.getQuantity());

    // 3. 扣减余额（支付服务）
    accountService.debit(orderDTO.getUserId(), orderDTO.getAmount());

    // 任一步骤失败 → 自动回滚所有已执行操作
    // Seata AT 模式：一阶段拦截SQL生成undo_log，二阶段异步清理
}

5. 熔断限流

// 基于 Sentinel 的熔断降级配置
@SentinelResource(value = "queryGoods",
    blockHandler = "queryGoodsBlock",
    fallback = "queryGoodsFallback")
public Goods queryGoods(String goodsId) {
    return goodsService.getById(goodsId);
}

// 限流处理：QPS 超过阈值时触发
public Goods queryGoodsBlock(String goodsId, BlockException ex) {
    return Goods.builder().name("系统繁忙，请稍后再试").build();
}

// 降级处理：服务异常时触发
public Goods queryGoodsFallback(String goodsId, Throwable ex) {
    return cacheService.getGoodsFromCache(goodsId);
}

生产部署忠告
不要用 Docker Compose 上生产：生产环境请使用 Kubernetes + Helm Chart，支持自动扩缩容、滚动更新、健康检查。配置外部化：所有配置通过 Nacos 管理，不要硬编码在镜像中。日志统一收集：EFK（Elasticsearch + Fluentd + Kibana）集中管理微服务日志。监控告警：Prometheus + Grafana 全链路监控，Sentinel Dashboard 实时熔断可视化。
