🌧️ 智能门锁天气/暴雨预警 — 提示词工程方案

基于华为/TCL/萤石/凯迪仕/小米等行业竞品对标，结合气象预警平台智能化趋势与天气API跨界融合实践，设计覆盖"多源数据融合→天气研判分级→气象预警响应→个性化建议→智能家居联动→AI智能体语音播报"全链路的天气守护提示词方案。

方案概述

智能门锁作为家庭入户的第一交互节点，具备"出门必经"的天然触达优势。本方案将门锁从简单的天气播报终端升级为AI天气守护管家，融合多源气象数据与用户画像，在用户出门时提供精准的天气提醒与出行建议，在极端天气时主动预警并联动智能家居守护家庭安全。

三大触发场景

场景A：用户出门时触发（被动提醒）

门内开门事件 → 拉取天气API+预警信号 → 读取传感器+用户画像 → 综合研判 → 语音播报+屏幕显示

场景B：极端天气主动预警（主动推送）

气象预警≥黄色 → 判断是否有人在家 → APP推送+屏幕轮播 → 建议/自动联动

场景C：定时天气播报（可选）

用户设定的出门时段（如工作日 07:00-09:00），在出门时段首次开门时播报，避免重复。

关键约束

准确性约束

⚠️ 天气提醒基于概率性预报：
  • 措辞必须体现不确定性（"预计""可能"），不得使用绝对性表述
  • 气象预警信号为确定性数据（政府已发布），可使用确定性措辞
  • 降水概率<30% → 不主动提醒带伞
  • 降水概率30-60% → "可能下雨，建议带伞"
  • 降水概率>60% → "预计下雨，请带伞"

打扰控制

严重度播报方式推送方式
0 晴好不播报（除非用户主动查询）不推送
1 轻微变化仅屏幕显示不推送
2 需关注屏幕显示+简短语音不推送
3 需防范屏幕显示+完整语音APP推送
4 需警惕屏幕闪烁+完整语音APP推送+建议联动
5 危险屏幕闪烁+紧急语音APP推送+短信+自动联动

语音生成规范

🎤 语音生成规范：
  • 语气：亲切关怀，非命令式（"建议带伞"而非"必须带伞"）
  • 长度：严重度0-2时≤30字，3-4时≤80字，5时≤120字
  • 人格化：可使用温和语气词（"请注意""记得""别忘了"），禁止恐吓性表述
  • 同一天气状况30分钟内不重复播报

降级容错

🔄 降级容错策略：
  • 天气API不可用 → 使用门锁传感器数据+最后已知天气数据，标注"数据可能不准确"
  • 气象预警信号源不可用 → 仅基于天气API数据研判
  • 智能家居Hub不可达 → 仅输出联动建议，不自动执行
  • 语音模块故障 → 仅屏幕显示+APP推送

Few-Shot 示例

示例1：晴好天气出门（不播报）

输入：晴天，25℃，微风，降水概率5%，无预警
输出：severity_level: 0 | voice_message: null | 不推送

示例2：小雨出门（简短提醒）

输入：小雨，18℃，降水概率75%，无预警，用户步行通勤
输出：severity_level: 2 | voice_message: "今天小雨，出门请带伞，注意路滑。"

示例3：暴雨红色预警主动推送（紧急）

输入：暴雨红色预警发布，预计3h降雨>200mm，有人在家
输出：severity_level: 5 | 自动关窗+收衣+关窗帘 | APP推送+短信+电话 | voice_message: "紧急！暴雨红色预警已发布..."

示例4：寒潮+老人在家（个性化）

输入：寒潮蓝色预警，降温12℃，最低-5℃，用户画像有老人
输出：severity_level: 3 | 个性化建议："家中老人请注意保暖，减少外出" | 建议预热空调

示例5：API不可用降级（容错）

输入：天气API超时，门锁传感器温度28℃湿度70%
输出：data_source: "sensor_fallback" | note: "天气API不可用，数据基于门锁传感器估算" | voice_message: "天气数据暂时无法获取，门外约28度，湿度较高，出门请留意天气变化。"
